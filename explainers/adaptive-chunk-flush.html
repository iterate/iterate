Adaptive chunk flush: the ephemeral lane stops steering

Click any event card: it expands to detail (YAML) and the right pane shows the state of the flush lane at that instant. Follow-up to #2531 (which coalesced per-token journaling into ~150ms windows but still awaited each window's Durable Object commit inside the drain). Times are realistic, not measured — except scenario 1's constants, which match prod measurements from 2026-08-27.

Takeaway — a lane that may LOSE data must never SLOW the producer.
  1. Before: the window flush was awaited inside onChunk — delivery throughput = window/(window + append latency) of provider rate. Fine at 60ms appends; degrades linearly with the DO.
  2. After: the flush fires un-awaited, cap of one in flight. While it pends, chunks keep flowing and simply widen the next window. A slow journal coarsens the UI (bigger, rarer windows); it never throttles the stream.
  3. The line is durable vs ephemeral: settle/context/usage stay awaited and atomic. Chunk events are forcibly ephemeral — evictable, gap-tolerant, not truth — and now behave like it end to end.
Reference — the moving parts
term what it is
pendingFlush The single un-awaited append promise, or null. Swallow-wrapped at creation (no unhandled rejection), cleared in a finally (a rejected append can't wedge the lane). Cap of one: no new flush fires while it's non-null.
flush trigger Chunk ARRIVAL only, when pendingFlush === null and the 150ms window (or 64KB) has elapsed. Never the pending append's settlement — that would make the DO commit rate the cadence. Never a timer.
merge Not a mechanism — an absence of one. flushChunkBuffer snapshots and resets the buffer synchronously, so chunks arriving during a pending append land in the fresh buffer and ride the next window.
drainChunkLane Turn-end epilogue, identical on success and catch paths: await pendingFlush → fire the tail → await it → then the atomic settle. One-time cost; keeps the no-chunk-after-settle invariant.
sequence gaps A rejected append loses its window's chunks; the sequence number is never reused. Consumers dedupe/sort by sequence and already tolerate gaps (eviction creates them). The committed assistant text extends the UI's windows to the full text at completion — total lane loss self-heals.
CHUNK_FLUSH_MAX_BYTES A flush trigger for a FREE lane, deliberately not a memory bound while one is busy: the buffer never outgrows the response, which partialText already duplicates.
