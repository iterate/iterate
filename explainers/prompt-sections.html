The life of a prompt

Click any event card: it expands to the full event (YAML), the right pane shows the actual provider request as of that offset — every render on this page comes from the REAL fold (buildAgentLlmRequestBody), pinned by the test fixtures in apps/os/src/domains/agents/prompt-scenarios/ — and the URL updates so you can link to any state. The standing document renders as ONE system message: the tagged document in first-appearance order (append order is the layout; hot content lands last simply because the worker's reaction arrives after the birth batch). Line highlights mark the diff vs the previous event; # lines carry the fixtures' commentary; the ✂ line marks where the provider's cached token prefix ends at each send (with permanent send stamps, that is everything except the newest suffix). Assistant turns are REAL raw outputs — they exhibit the rules that were in force when they were generated, which is what makes the replace-vs-append question visible.

The opinion — re-adding a key is the update; temporal position is the coherence mechanism. A standing instruction reads as timeless, and the standing document sits ABOVE every turn — so editing it both busts the cache for the whole conversation behind it and can manufacture "history contradicts my instructions". The design avoids both by construction — and the kernel knows NO key by name: keys are fully arbitrary strings, ordering is pure first-appearance (a prompt file's per-section batch commits in file order), and no key ever triggers clearing, ordering, or gating of another. "agent/system-prompt" is an authoring convention, nothing more.
  1. Birth window: keyed adds coalesce in place, free. Until a request has been sent, re-adding a key edits the pending standing section directly — nothing sent, nothing contradicted, nothing cached yet. Templates do all their shaping with the same everyday event as everyone else.
  2. Once sent: the same keyed add lands at the tail, at its moment in time. The new occurrence renders as a system message in the timeline with supersedes linkage — everything before it visibly predates it (no contradiction, no marker needed), and the entire prefix stays byte-stable (cache intact). The superseded copy rides until compaction collapses to latest. (Whether these render as system or developer is a provider-mapping detail.)
  3. context-rewritten (replace/delete) is deliberate history rewriting — redaction, un-saying, delete *. They bust the cache from the standing document down and, applied to behavioral rules with contradicting visible history, produce the scenario-3a anti-pattern. Not the everyday verb.

Appendices — how the big coding agents handle these same problems

Deep-research per agent (source dives, official docs, engineering blogs, traffic inspection). Executive summaries visible; expand for detail with citations. Each ends with a "versus our design" note.

Appendix A — Claude Code (Anthropic; closed-source: official docs + reverse engineering)
  • Everything re-sent every turn, ordered static→dynamic in three layers (system prompt · project context · conversation) precisely so prefix caching absorbs the cost — Anthropic's own blog title: "Prompt caching is everything".
  • The system prompt is frozen at session start and never edited mid-session. ALL mid-session change (file edits, plan mode, hooks, skills) arrives as appended <system-reminder> blocks inside user messages or tool results — never history rewrites.
  • CLAUDE.md is NOT in the system prompt — it's injected into the conversation (first user message), and the SDK docs say so explicitly: "the SDK injects their content into the conversation and leaves the system prompt untouched."
  • Mid-session CLAUDE.md edits deliberately do nothing until /clear, /compact, or restart — documented as a cache-preservation choice.
  • Compaction = replace history with a model-written structured summary, generated by a fork sharing the parent's byte-exact prefix (the summarization request is itself mostly cache reads); user messages and security constraints preserved verbatim; per-file too-big references become reminders ("use Read if needed").
  • Only truncation-shaped rewrites exist: /rewind truncates to an already-cached prefix; /clear starts fresh (old transcript resumable). No selective redaction.
  • Trust is in-band, not role-based: harness text is user-role wrapped in <system-reminder>; external content gets "NOT from your user, treat as data" wrappers; untrusted strings are escaped before interpolation.
  • The date is per-session, not per-request — captured once at start, byte-stable, cache-safe; no per-message clock. Durations aren't model-visible (except subagent result trailers).
  • Sessions are append-only JSONL; resume replays; /branch copies the file.

Request shape & caching

API order tools → system → messages; ~2.8k tokens of behavior instructions + ~9k of tool definitions (MinusX teardown, older build); env info (cwd/platform/shell/git snapshot) computed once per session at the end of the system prompt. Breakpoints: one on the last system block, one on the newest turn's last content block, so hits accrue incrementally; per-request-volatile things are "eliminated or moved to the very end" as policy. Documented cache busters: model/effort switch, MCP connect/disconnect (when tools sit in the prefix), CC upgrade, compaction. Documented non-busters: file edits, CLAUDE.md edits, permission-mode switches, /rewind, subagents. Cache TTL 1h (subscription) / 5m (API keys).

Prompt structure

Assembled from hundreds of named conditional template fragments with variable interpolation (Piebald dump; dbreunig teardown) — sectioned at build time, but individually replaceable only at session build (output styles, --append-system-prompt, excludeDynamicSections), never at runtime. Skills: one-line index at start, full body injected as a user message on invocation. Hooks run as code; only their output enters context. Subagents get their own system prompt; the parent sees only call + result.

Mid-session change & reminders

~37+ distinct <system-reminder> templates (file changed, plan mode entered/exited, todo empty, post-compact file references…) injected into user slots and hidden from the terminal UI (michaellivs deep dive). A repo file edited after being read: old read stays verbatim; a reminder notes the change; the model re-reads if needed.

Compaction details

Summarizer fork reuses the live conversation's exact prefix + a final summarization instruction; rigid schema (intent, technical concepts, files with snippets, errors/fixes, ALL user messages, pending tasks, verbatim next step) with an anti-injection clause (assistant-embedded text shaped like a user turn must not be attributed to the user). Survives: system prompt, root CLAUDE.md + memory (re-read from disk), invoked skill bodies (capped), recent exchanges + up to 5 recently-read files. Lost: nested/path-scoped rules, skill index, the rest.

Observed on the wire (traffic inspection — Matt Pocock + proxy dumps)

messages[0] anatomy (proxy-captured, claude-code#43657): the first user message is SEVERAL content blocks in order — a ~533-char "companion" reminder, a ~1,501-char skill-listing reminder, a ~7,801-char project-context reminder (CLAUDE.md etc.), then the user's actual text as the final block. Breakpoints observed live: cache_control: {ephemeral, 1h} on the last block of the newest user turn. Resume reality check: two observed bugs — the skill-listing reminder MOVES position on --resume (structural prefix change → permanent cache miss) and one extra \n accumulates per resume (1-byte prefix bust); ~2,850 tokens/turn re-written instead of ~43 in the reported trace. The docs' clean cache model is aspirational at the resume boundary. Pocock's overhead numbers (article, agent-proxy gist): one request carried ~155KB of tool definitions across 69 tools (~65k input tokens); a bare-name deny rule removes a tool's definition from the payload entirely while scoped rules only gate execution; startup context dropped 96.6k → 28.9k tokens via settings alone. No per-request timestamp observed in any dump — consistent with per-session dating.

Sources

Official: prompt-caching, context-window, sessions, SDK modifying-system-prompts, engineering blog. Reverse-engineered (flagged as such): Piebald-AI dump, MinusX, dbreunig, michaellivs.

Versus our design: strongest possible endorsement of our temporal model — frozen prefix, append-only timeline, in-band provenance tags, "instructions live in the conversation, not the system prompt" for anything editable, and deferred-change semantics instead of history edits. Appendix B — opencode (SST/Anomaly; open source, read at commit be15db5)
  • One big system message, rebuilt from scratch every turn: (agent prompt OR provider-family prompt picked by model-id substring) + env block + AGENTS.md/CLAUDE.md + MCP instructions + skills list, joined into a single string (session/llm/request.ts).
  • Provider-family prompts: claude→anthropic.txt, gpt→gpt/codex.txt, gemini→gemini.txt… — switching model mid-session silently swaps the entire prompt head.
  • Rules files are re-read every request and applied in place — mid-session edits just change the system message next turn (cache bust accepted, unversioned).
  • Mode/plan context arrives as ephemeral synthetic user parts (<system-reminder>-wrapped), re-appended to the latest user message each turn — not system edits.
  • Caching: Anthropic-family gets cache_control on ≤2 system messages + the last 2 non-system messages; OpenAI-family gets promptCacheKey = sessionID; per-request identity lives in HTTP headers, not the prompt. Only volatile prompt value: day-granular date.
  • Compaction is a task in the message stream: a hidden no-tools agent summarizes a serialized transcript into a structured template; old messages are filtered at request-build time, never deleted; a token-budgeted verbatim tail (~25% of usable, 2k–15k) replays after the summary. Opt-in "prune" blanks tool outputs older than a 40k-token window with [Old tool result content cleared].
  • History is mutable-by-upsert (SQLite; parts updated in place while streaming) with git-snapshot-backed undo/redo that really deletes reverted messages; fork clones a session.
  • Big tool outputs spill to whitelisted temp files (2000 lines/50KB cap) with a preview + pointer. Durations stored, never model-visible.
  • Trust is thin: injected content is user-role synthetic text; the only defense is prompt text declaring <system-reminder> system-authored; MCP instructions go straight into the system prompt.

Request shape

Per turn the loop reloads ALL messages from SQLite, applies filterCompacted, and rebuilds: system string (2-system-message cap chosen to match the 2 cache breakpoints), then stored parts → AI-SDK messages with per-provider sanitizers (empty-content filtering, toolCallId scrubbing, reasoning-part downgrades on model switch). Tools alphabetically sorted for determinism. OpenAI-OAuth puts system text in the Responses-API instructions field.

Instructions & agents

Global then project AGENTS.md/CLAUDE.md/CONTEXT.md (first match wins walking up to worktree root — deliberately no ancestor stacking), plus config globs and URLs (5s timeout). Subdirectory AGENTS.md lazy-load: reading a file attaches not-yet-seen instruction files to the tool output inside <system-reminder> tags, deduped per message. Agents: build/plan differ only by permissions (plan denies edits); a custom agent prompt REPLACES the provider prompt wholesale — no partial override (the exact clumsiness our sections exist to fix).

Compaction mechanics

Trigger: last assistant's tokens ≥ input limit − ~20k, or /compact. The compaction part is itself a message in the stream; the summarizer gets no system prompt and no tools — just a serialized transcript (tool outputs pre-truncated to 2k chars) + a template (Objective / Important Details / Work State / Next Move / Relevant Files), with prior summaries folded in ("anything you do not carry into the new summary is lost"). Post-summary the request renders as [synthetic "What did we do so far?", summary, verbatim tail, …]. Auto-continue injects a synthetic user nudge.

State

SQLite (drizzle) MessageTable/PartTable, ULID-ordered; share/unshare live-syncs full history to a web replay; subagents are child sessions surfaced as one task part + a synthetic summarize nudge. A v2 pipeline (packages/core: context-epoch, projector, its own compaction) is in-progress behind flags — not fully traced.

Versus our design: opencode takes the opposite bet on standing content — re-read files + in-place system-message change, accepting cache busts and losing temporal coherence (a rules edit mid-session is exactly our scenario-3a shape, unmarked). Its compaction-as-a-message-in-the-stream and filter-at-render (never delete) rhyme strongly with our fold projection; the verbatim recent tail is a good idea we haven't discussed (our compaction could keep one). The whole-prompt agent override is the anti-pattern our keyed sections retire. Tool-output spill-to-file matches what codemode-tag already does.
Appendix C — Codex CLI (OpenAI; open source, Rust, read at commit 7781f0a)
  • Stateless full-replay requests: every request sends store:false, the whole transcript as input, base instructions in the Responses-API instructions field, and encrypted reasoning included so it survives client-side. No server conversation state; caching is the only reuse.
  • The star finding — "world-state sections": our keyed temporal supersession, independently invented. Mutable context (AGENTS.md, environment, permissions, model, tools…) is modeled as typed sections with STABLE IDs that snapshot to JSON; before each request Codex diffs current-vs-baseline and APPENDS only changed fragments as new messages. The prefix is never rewritten mid-thread.
  • AGENTS.md is a user-role message, re-read from disk every step; a mid-session change appends a replacement message — "These AGENTS.md instructions replace all previously provided AGENTS.md instructions." — old text stays in history. That is literally our supersedes semantics, in prose.
  • Cache discipline is TESTED: integration tests assert the previous request's input is a byte-identical prefix of the next and prompt_cache_key (= session id) stays constant across settings overrides — our "superset property" as CI. The WebSocket transport exploits the same invariant to send only item deltas.
  • Time is appended, never interpolated: the date lives in an <environment_context> section (re-appended on rollover) and an optional <current_time_reminder> developer item on an interval — suffix items, cache-safe. Same conclusion as our request-event stamps.
  • Compaction replaces history wholesale ("Memento"): re-injected initial context + last ≤20k tokens of REAL user messages + summary-as-user-message with a fixed handoff prefix; also a server-side /responses/compact variant with encrypted summary items. Auto at ~90% of window; users are warned repeated compaction degrades accuracy.
  • Tool outputs are structured items with text bodies: Exit code / Wall time: 2.3 seconds / Output — durations model-visible (the only agent of the four that does this), middle-truncated AT RECORD TIME so history permanently holds the truncated form.
  • No system role at all: base prompt in instructions; policy → developer; workspace-derived → user, distinguished from real user intent by MARKER TEXT (and excluded from turn-boundary/rollback semantics by marker matching).
  • Persistence is an append-only JSONL rollout (+zstd+SQLite index) including world-state merge patches, so resume reconstructs the diff baseline exactly; fork = truncate at a user-turn boundary.

World-state mechanics

Two layers: ContextualUserFragment (40+ fragment types with open/close markers and content-kind tags, so fragments are recognizable in retained history) and WorldStateSection (stable ID + JSON snapshot holding "only the comparison data needed to decide what the model must be told next"; render_diff(previous) emits a fragment only when the section changed). Per-step: rebuild, diff, append; the RFC-7386 merge patch is persisted to the rollout AFTER the history it describes. Model switch mid-thread appends a <model_switch> fragment carrying the new model's full instructions while the instructions field stays pinned — even the system prompt is superseded temporally.

Cache & ordering discipline

Tests: "The entire prefix from the first request should be identical and reused as the prefix of the second request" (prompt_caching.rs). Busters: model/tool-list/reasoning-format changes, compaction, rollback; during overflow-recovery it trims from the BEGINNING "to preserve cache (prefix-based) and keep recent messages intact". Item ids not issued by the server are stripped pre-send. Subagents key their cache as {source}:{parent_thread_id}.

History & rollback

Append-only COW vector with a history_version bumped only by the deliberate rewrites: compaction, rollback (drop_last_n_user_turns — trims contextual fragments above the cut and clears the diff baseline so context fully re-injects), and overflow trimming. Per-request normalization pairs calls/outputs and silently DROPS any system-role message. No content redaction beyond record-time truncation.

AGENTS.md composition

Walk cwd→project root, override>AGENTS precedence per dir, `~/.codex/AGENTS.md` prepended, joined under a 32KiB budget, wrapped in <INSTRUCTIONS> markers. Untrusted projects get none. Nested dirs BELOW cwd deliberately not injected — the base prompt tells the model to check for them itself.

Appendix D — pi (Mario Zechner / earendil-works; open source, repo read at pi-mono HEAD)
  • The request is rebuilt from scratch every turn — one system string + a message list projected from an append-only JSONL session TREE (entries with id/parentId, a moving leaf pointer). Prefix stability falls out of determinism, not machinery.
  • Tiny system prompt (~500 tokens), assembled from ordered parameterized parts (base → tool one-liners → guidelines → <project_context> with each AGENTS.md in a path-attributed tag → skills index → cwd) — addressable options to one builder, concatenated to a single block.
  • AGENTS.md lives in the system prompt, snapshotted at session start; /reload swaps the prefix in place — history never rewritten, cache busted from byte 0, accepted.
  • Caching is provider plumbing: Anthropic breakpoints on system + last tool + last user message (optional 1h TTL); OpenAI prompt_cache_key = session id. Compaction/summary calls deliberately use fresh ids + cacheRetention: "none" so one-off prompts don't pollute the cache.
  • No dates or timestamps ever reach the model — every internal message is timestamped, all stripped at the provider boundary.
  • Compaction (added recently): threshold-triggered, keeps ~20k recent tokens verbatim, appends a structured summary ENTRY (Goal/Constraints/Progress/Decisions/Next/Critical) with an iterative must-preserve update variant + cumulative file lists; nothing deleted; hooks can cancel/replace it.
  • No history rewriting at all: no /clear (new session file instead); branch switching appends and moves the leaf; the only removals are per-request transforms by extensions that never touch the stored log.
  • Two-channel tool results (content → LLM, details → UI); bash output truncated to last 2000 lines/50KB with the FULL output spilled to a temp file whose path rides in the result. No durations.
  • No trust tiers in content — everything flattens to user role; safety is operational ("containerize pi"), plus a project-trust gate on loading repo extensions.
  • Mario's stated ethos (directly relevant to us): total observability, no hidden injections ("harnesses inject stuff behind your back"), no per-release prompt churn ("I hate that"), prompts-are-code/files-are-state, and "the prefix cache is derived state… a pure performance optimization."

Request building & structure

agent-loop.ts: "transforms to Message[] only at the LLM call boundary" — context.messages → optional transform → provider convert. App-level roles (bashExecution, extension injections, branch/compaction summaries) all flatten to user messages with fixed wrappers. Steering messages typed mid-run are injected between tool results and the next call. AGENTS.md discovery: global, then every ancestor of cwd (root-most first), override>AGENTS>CLAUDE precedence, worktree shadowing. Skills are an XML pointer index; the agent reads SKILL.md itself.

Change semantics

Context files read once at session start; /reload rebuilds the prompt (prefix swap; resume also uses CURRENT files — the session file stores no system prompt). Extensions may override the system prompt for one turn (scoped mutation, reset after). Model/thinking changes are appended session ENTRIES — replayed on resume, i.e. config-as-history where it matters.

Compaction details

Trigger at window − 16k reserve (manual /compact, threshold, or overflow-recovery with turn retry). Cut at a turn boundary after accumulating ~20k keep-tokens; over-budget single turns get split-turn double summaries. Serialization clips tool results to 2k chars and renders as labeled text "so the model doesn't treat it as a conversation to continue". Result: an appended CompactionEntry; render = summary-as-user-message + kept entries. Old entries stay on disk forever.

Notable machinery

A length stop reason fails ALL tool calls in that message rather than executing possibly-truncated args. excludeFromContext flags drop user-run bash from renders. Session format doc is public (docs/session-format.md).

What to take from this — graded

An earlier draft of this list called everything a "steal"; on review, most items are tests, deferred notes, or receipts for bets we already made. The honest grading:

  • Genuine steal, near-term: a truncated model reply is never executable (pi: a length stop-reason fails ALL tool calls rather than running possibly-truncated arguments). How: the response interpreter refuses script extraction when the assistant reply ended on max-tokens; corrective feedback is appended instead.
  • A test requirement, not an idea: the byte-identical-prefix invariant (Codex tests it in CI; Claude Code's observed resume drift — a moved reminder block, one stray \n — shows why vigilance isn't enough). How: a spec renders consecutive requests from the fold and asserts request N is a strict prefix of request N+1 absent rewrites/compaction. Belongs on the slice-1 checklist.
  • Slice-3 notes (the compaction bundle) — parked until compaction is rebuilt as a range rewrite: keep a verbatim recent tail (~20k tokens, cut at a turn boundary — opencode/Codex/pi all converge here); a rigid summary schema preserving user messages and security constraints verbatim, with Claude Code's anti-injection clause; cumulative read/modified file breadcrumbs across compactions (pi) so the post-compact agent re-reads instead of rediscovering; and on cache strategy note that pi and Claude Code take OPPOSITE approaches — pi isolates one-off summarizer calls from the cache, Claude Code deliberately shares the warm prefix (its summarizer fork replays the conversation's exact bytes, so summarization is mostly cache reads). Ours favors Claude Code's: a summarizer that re-reduces the same events gets the prefix for free — and since compaction is just a rewrite op in our vocabulary, the summarizer may simply be an ordinary capability call or agent turn, the way titles already happen in-band via summary-updated.
  • Slice-2 audit item: provenance, not role, answers "was this really the user?" (Codex excludes marker-tagged contextual user messages from turn-boundary and rollback semantics). How: when provenance lands, audit every fold site that keys off user-role — contextTriggerSource's external classification, the autonomous-turn breaker reset, failure-streak reset — so a worker-appended webhook text doesn't reset budgets the way a human message does.
  • Validation with receipts, already shipped: model-visible durations (scenario 1b; Codex's "Wall time" is the only other example in the field). Nothing to do — the settlement renderers print the measured duration.
  • Validation with receipts, already fundamental: capability catalogs as pointers (Pocock measured ~155KB of tool definitions across 69 tools riding EVERY Claude Code request; pi refuses MCP for the same reason). This is the codemode + lazy itx.docs discovery bet, quantified by others' pain — the differentiator, not a steal. Treat any future per-capability schema-injection proposal as guilty until proven cheap.
