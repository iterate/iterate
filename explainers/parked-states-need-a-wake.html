Parked states need a wake

Click any event card to expand it; the right pane shows the event plus the system state after it — what's durable, what's in-memory, what the user sees. Times are real where a journal exists (preview_6, 2026-08-27) and realistic elsewhere. Red-edged cards are where the system goes dark. Consolidated in PR #2530; task file tasks/platform-stall-repros.md.

The takeaway — one gap, five hats: work parks with no wake condition, so progress waits for luck. The platform re-drives work on delivery (an event arriving). A state that's waiting — an in-flight LLM attempt, a halted subscription, a failed bootstrap — carries no deadline of its own. If no event happens to arrive, nothing notices. The five hats:
  1. Mid-stream LLM stall (#2510) — hung attempt, never settled. Quiet stream: dark ~15min.
  2. Eviction-churn re-dial hang (new) — eviction recovers in 10s, but the re-dial hangs too; each cycle burns a 30–40s staleness window. First turns took 150s/183s on preview.
  3. Halted subscription (#2486) — parked forever until an operator noticed. Fixed for one wake (deploy); the fix's own retry has the same bug one level down.
  4. Bootstrap killed by transient (#2513) — retryable failure classified terminal. Parked permanently.
  5. Facet pin false alarm (#2518) — the observability twin: state changes with no recorded why, so a test can't tell cause from coincidence.
The fix direction: every waiting state derives a nextDeadlineAt from reduced state; the host arms its Durable Object alarm at the minimum; firing runs ordinary reconcile. Derived-from-state means recomputed on revival — it survives eviction by construction. Details in the last section.
Reference — terms you need (skip if you live in this repo)
term meaning
obligation Work a stream processor owes because of a journaled event — e.g. "open LLM request at offset 44 needs an answer". Re-derived from reduced state on every catch-up.
delivery-driven Obligations are only checked when an event delivery wakes the processor. No delivery → no check → no progress. The villain of this explainer.
incarnation / eviction / revival One in-memory life of a processor's Durable Object. Eviction kills it (memory pressure, deploy — routine on loaded previews). A keepalive alarm boots a successor, which appends a processor-revived fact — itself a delivery, which is what re-drives obligations.
keepalive alarm The DO alarm the durability layer keeps armed (~10s lead) so an evicted processor gets a successor. The only self-driven clock the system has today.
staleness wake stream/woken — a paced alarm-driven check that notices "nothing has happened for a while". 30–40s granularity. Coarse by design; it was never meant to be the attempt watchdog.
wedge breaker Keepalive's crash-loop detector: ~90 busy refires × 10s ≈ 15min, then a forced revival. Today it is the effective ceiling on a hung attempt in a quiet stream.
retry ladder The agent's 3 LLM attempts spaced 10/20/40s (#1826). Starts only when an attempt fails. A hung attempt never fails — the ladder never starts. Load-bearing detail.
intercepted model / pager intercepted/* models are served by a handler in the test's own process, reached back over a hibernatable "pager" WebSocket to the project DO. Free deterministic agent turns; also a long fragile wire during churn.
halt / antidote A fan-out subscription whose receiver keeps failing is halted (stop skipping events). #2486's fix: the halt records the deploy version; a send check under a different version resumes it once.
reduced state The fold of the journal. Anything derived from it is recomputed identically by any incarnation — the property the fix leans on.

Event + state

The fix direction, concretely

One rule: a processor's reduce exposes nextDeadlineAt(state) — the earliest moment any waiting state stops being acceptable. The host arms the DO alarm at min(keepalive, nextDeadlineAt), persists the desire next to the keepalive record, and on fire runs the ordinary catch-up/reconcile. No new recovery entrypoint. This extends tasks/agent-llm-deadline-alarm.md (which sketched it for the 10-min expiry horizon — proven live by two prd requests that sat expired for four days).

hat deadline derived from on fire
1–2 LLM attempts min(lastProgressAt + chunkIdleBudget, expiresAt) — dial and chunks are already journaled abort in-flight slot, settle attempt failed → the 10/20/40s ladder owns re-dialing
3 halted subscription haltedAt + reprobeBackoff, plus the existing deploy antidote; a stale-version halt IS durable evidence of an owed resume one paced resume attempt; re-halt if still broken
4 bootstrap saga classify registry-propagation failures transient → park with retryAt instead of terminal retry the resolution step
5 facet pin n/a — provenance, not a deadline: rebuilds record their trigger ("source-commit abc123" vs "cold-boot"), like halts now record workerVersion the pin asserts causality instead of coincidence

Why derived-from-state instead of "arm an alarm when you start waiting": an imperative arm is in-memory intent — eviction loses it, and any recompute-from-durable-state pass clears it (exactly the Bugbot edge in #2486's own retry). A derivation can't be lost: every incarnation recomputes it from the same journal.

Budgets (chunkIdleBudget etc.) are product decisions the fix makes; the expected-fail specs pin 60s placeholders, same convention as #2510.

Appendix — how other systems handle this

Every mature job system makes "waiting" carry a clock, none trusts the worker to report its own death:

  • SQS: visibility timeout — an unacked message reappears on its own. The queue owns the deadline, not the consumer.
  • Temporal: every activity has start-to-close / heartbeat timeouts enforced by the server; a silent worker's task is rescheduled at the deadline, from durable state.
  • Sidekiq / Celery: ack-late + reaper processes that re-enqueue jobs whose worker vanished, found by scanning durable in-progress sets on a timer.
  • Cloudflare DO alarms: the native primitive this fix uses — one durable alarm per object, survives eviction, exactly-once-ish fire. The platform already pays for it via keepalive; the fix widens what it watches.

The common shape: deadline lives with the durable record of the work, enforcement is the scheduler's job. The consolidated fix is the same idea expressed in this repo's grain: the journal is the durable record, reduce derives the deadline, the DO alarm enforces.
