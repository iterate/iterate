CI Inherit and Reuse

Every push to a pull request used to deploy the whole product (seven Cloudflare Workers) and run both test suites. That took about 2¼ minutes, even for a typo fix.

Now CI looks back at the pull request's last push that already did the work. Whatever the new push didn't affect, it skips: a test suite passes straight away or runs only the tests that changed, and the deployment is reused when nothing that deploys changed.

How it decides

  • Each test suite looks back to the last push it passed on. If nothing it depends on changed since, it passes without running. E2E tests only test the platform (apps/os); Browser specs use every app.
  • A suite that has to run runs only what changed when it can: just the edited test files, or just the specs for the app that changed. A platform change runs everything.
  • The deploy looks back to the last push that deployed. If nothing that deploys changed since, it reuses that deployment. Otherwise it deploys everything.
  • A failed result is never reused. After a red run, the suite runs again.

The catch: CI now tests the pushed commit itself, not the commit merged with the latest main. A branch that's fallen far behind main should merge main in. This is an experiment in pull request #3340.
