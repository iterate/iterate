## 1. Snapshot summary

The headline: **codex has already executed two things the plan scheduled and
reversed one thing the plan praised.**

1. `device_event_stream` + `callback_budget` are **finished and fully wired**
   (untracked files, but built, tested, in the device profile, in main.cpp,
   in the simulator, in CMake). Not "being written" — written.
2. The **peer-delivery guard is deleted wholesale** — module, header, test,
   policy constants, compile-time proofs, conductor coupling, metrics fields
   (~1,714 lines + spread). Reason recorded in the code: a WebSocket PONG
   proves only hop-level ordered parsing, never userspace-proxy or provider
   receipt, and using it as PCM delivery credit **stalled long push-to-talk
   behind a false acknowledgement boundary**. Client-originated PING is gone
   from `websocket_tx` entirely (two slots now: reply-PONG + CLOSE). PCM
   freshness is now governed only by local facts: capture age, per-frame send
   duration, send-no-progress timeout, generation purge.
3. The tree **shrank ~1,100 net lines while adding the event stream** —
   requirement 1 is being paid down without the plan's involvement.

Also in the working tree since this morning: the −18 dB ES8311 brownout fix
(uncommitted but present), an 8 KiB shared TLS-owner task stack (crash-proof
provenance in a comment), a `network` object in control diagnostics (schema
v3), a flattened-path dispatch bridge for OS live mounts (with a small vendor
capnweb addition), and a resumable-WebSocket-header patch in the
tcp_transport override.

## 3. Adopt list — what codex's implementation does better than the plan's sketch

Things to lift into the plan as-is (mechanisms, names, shapes, bounds):

1. **The PONG lesson as a standing design rule.** "A hop-level control reply
   is never end-to-end delivery credit; freshness and liveness are governed
   by observable local facts (capture age, send duration, byte progress) plus
   application-level signals." This belongs in DECISIONS as its own entry —
   it retires the plan's "confirmed delivered frame" vocabulary (facts row 9)
   and pre-empts anyone re-inventing a ping-credit scheme for the D8 media
   lifecycle.
2. **The notification wire shape** for any generalized event delivery:
   `{schemaVersion, sequence, type, source, result, snapshot,
coalescedNotifications}`. Specifically worth copying: an explicit
   `schemaVersion` from day one; `snapshot` as a first-class resync marker
   (a reconnect during a held button restores state without inventing an
   edge); and coalescing that is **detectable by the receiver** (sequence gap
   - cumulative counter) so userspace must reset an ambiguous turn instead of
     guessing which transition was skipped. This slots straight into D4/D5.
3. **Latest-state-wins with explicit loss**: on queue saturation, replace the
   newest queued entry (preserving older causal order) rather than dropping
   oldest or blocking. The plan's event machinery never specified its
   overflow policy; this is the right one for state-bearing control events.
4. **Release-before-replace ownership handoff** for callback subscribers, and
   its two edges: idle callbacks are replaceable on the same session (worker
   generations turn over without device reconnects — fixes a real production
   503 loop), in-flight callbacks are not (completion would ambiguate
   ownership), and a refused replacement still releases the offered import so
   retries cannot leak capabilities. Rejected callback = ended subscription,
   never a retry storm.
5. **Session-end state preservation**: on control-session death, drop the
   imported callback and queued deliveries but keep the boot-local sequence
   and current physical state — they are precisely what the replacement
   session's first snapshot needs. Aligns exactly with D5's
   `bootCounter:sequence` idempotency; the generalized stream should keep it.
6. **The shared callback budget as transport-burst arithmetic**: capacity
   derived from the control-ring proof (one callback = push+pull outbound,
   resolve+release inbound), acquired only when a delivery is actually ready,
   backpressure = "try a later poll", underflow = loud STATE_ERROR. Also the
   module-ordering corollary (events outrank metrics for slots) — facts
   row 16.
7. **The 8 KiB TLS-owner stack as one named shared constant** with crash
   provenance in the comment, plus the reasoning that different per-caller
   budgets just postpone the same crash to the second socket. Take the
   constant, the name, and the "evidence may later justify smaller" clause
   into the DIRAM ledger.
8. **The flattened-path envelope** (`flattenNestedPaths` on provide,
   `invokeCapability({path, args})` on dispatch, non-recursive unwrap guard):
   it keeps the device's static method table as the single dispatcher and
   costs no queue or realtime work. Any v2 capability surface (call_control)
   should ride the same bridge rather than adding routing formats.
9. **The honesty pattern for optional observations**: `has_wifi_rssi_dbm`
   beside `wifi_rssi_dbm`, absence as "the only honest evidence" during a
   roam, sampling pinned to the low-rate diagnostics path. The stage-3
   generated schema should make this evidence-flag pattern the default for
   any optional field, as `has_buffers` already does.
10. **The resumable-WebSocket-header patch + host test for patched IDF
    source** (facts row 13): a template for how the plan's stage-2 transport
    fixes should be proven — patch the vendored layer, compile the patched
    source on the host, fault-inject there.
11. **The serial-port ground rule** (facts row 17): diagnosis procedures and
    rig tooling identify devices by USB metadata and treat every serial open
    as a reboot.

## 4. What this changes about plan risk

- The riskiest plan sentence ("peer_delivery_guard … strongest code in the
  tree") is dead; the risk inverted — the plan must now _not_ carry deleted
  concepts forward in its stage-2 wording. Rows 5 and 9 are the edits that
  matter most.
- Codex's trajectory is convergent with the plan, not divergent: it deleted
  turn-adjacent machinery (delivery guard), landed the event stream the plan
  wants to generalize, is already doing net line reduction, and its metrics
  `network` object is a step toward requirement-10 observability. Stage-4's
  "generalize in place" got cheaper today.
- Two plan bugs need re-verification before stage 2 (rows 9 and 10): one fix
  needs rewording, one may already be fixed.
- Budget/memory numbers (row 12) and line counts (rows 7, 8) drift daily;
  every number in the plan that describes "today" should be dated against
  the codex checkpoint commit when Jonas names it (G2).
