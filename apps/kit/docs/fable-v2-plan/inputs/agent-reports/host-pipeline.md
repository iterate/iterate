# Host-side (TypeScript) voice/audio pipeline — architecture deep-read

All paths under `/Users/jonastemplestein/.herdr/worktrees/iterate/c-capabilities/apps/kit` (abbreviated `KIT` below for prose; file references are absolute).

## 1. End-to-end shape of the host voice stack

**Wire contract (v1).** Mono PCM16LE, 16 kHz, 20 ms frames = 320 samples = 640 bytes per binary WebSocket message, subprotocol `iterate.kit.pcm.v1`; a single zero-length binary message is the ordered end-of-response marker. This is stated in the goal doc (`KIT/docs/physical-device-voice-goal.md` §Audio), declared on the host in `src/voice/device-pcm-proxy.ts:5,31`, and mirrored in firmware at `firmware/components/core/include/iterate/kit/pcm_websocket.h` (`SAMPLE_RATE_HZ=16000`, `SAMPLES_PER_FRAME=320`, `FRAME_BYTES=640`, subprotocol macro).

**Topology.** The device holds two independent long-lived WebSockets to one host fetch handler (`src/device/local-device-peer-server.ts:59-114`):

- `/api` — ordinary Cap'n Web control (capabilities, PTT start/stop, metrics/diagnostics subscriptions) via `newWebSocketRpcSession`.
- `/pcm` — the binary PCM lane, handled by `DevicePcmProxy.fetch` (`src/voice/device-pcm-proxy.ts:159`).
  The same handler is fronted either by a Captun tunnel (`tunnels.iterate.com`) or a direct-LAN Node server (`LocalFetchWebSocketServer`) — deliberately the _same_ fetch/peer code so a direct-LAN pass isolates tunnel cadence rather than proving a friendlier server (`scripts/device-e2e.ts:350-386`).

**Auth.** The proxy authenticates a project id (header `x-iterate-project-id` or `?projectId=`) plus a bearer token from either `Authorization: Bearer` or a base64url-encoded `iterate-bearer.<token>` subprotocol for clients that can't set headers (`device-pcm-proxy.ts:104-112, 178-187, 901-923`).

**Provider seam.** `connectProvider(session) => Promise<WebSocket>` is the single pluggable seam. Production/e2e-voice uses `connectGrokRealtimeVoice` (`src/voice/grok-realtime-voice.ts`): the long-lived xAI key is used only on one HTTPS call minting a 300 s client secret; the WS connects to `wss://api.x.ai/v1/realtime?model=grok-voice-think-fast-2.0` carrying the secret as subprotocol `xai-client-secret.<v>`, then a `session.update` fixes binary headerless PCM16 at 16 kHz both ways, `turn_detection` manual (PTT) or `server_vad`, voice `eve`. Deterministic fixtures (`DeterministicPcmToneProvider`, `DeterministicPcmPrbs31Provider`) speak the identical provider contract (`response.create` / `response.created` / binary PCM / `response.done` / `response.cancel`) over a captun `WebSocketPair`, so a physical run swaps only the signal source, not the plumbing.

**Downlink path.** Provider binary PCM is admitted into a fixed 8-frame (160 ms) ring (`#downlinkQueue`, `device-pcm-proxy.ts:14,339`), starts only after a 3-frame (60 ms) startup reservoir (`:24,644-651`), then flows in one of two explicit delivery modes (`:62,69-84`):

- `host-paced` (default): a JS timer emits one 640-byte frame per 20 ms on an absolute deadline grid (`pcm-frame-pacer.ts`); a post-start empty-queue deadline is a terminal `provider-downlink-source-underrun` (`:678-691`) — never pause-and-replay.
- `device-clocked`: forward each bounded burst immediately; the firmware's I²S descriptor clock and freshness-bounded ring own late/drop/reset policy (`:719-734`).
  After `response.done` drains, the zero-length EOS marker is sent and the generation's clock state resets (`:777-786`). Overflow, underrun, egress backpressure, protocol violations each close _both_ sockets with typed application codes (4013 backpressure / 4011 counterpart / 4002 protocol, `:32-36`) — "generation" death and reconnect-with-fresh-audio is the universal recovery model, exactly matching the firmware's epoch semantics.

**Uplink path.** Exact 640-byte device frames are relayed verbatim to the provider; text or wrong-sized binary on the uplink is a protocol error (`:462-500`). PTT choreography: `inputStarted` clears/suppresses downlink and cancels an active response; `inputStopped` (after any in-flight Blob conversion) sends `input_audio_buffer.commit` + `response.create`; `requestTextResponse` injects `conversation.item.create` + `response.create` for text-driven turns (`:383-448`) — this is what tone/PRBS/grok-playback-only runs use.

**Diagnostics side-channel.** Provider JSON events never enter the PCM lane; they surface via `onProviderEvent` (logged as `would_post_to_stream` — the future stream-posting hook, `scripts/device-e2e.ts:314-326`). Socket closes surface as structured `DevicePcmSocketClose` evidence (origin/classification/code/reason/wasClean, `device-pcm-proxy.ts:47-58, 843-873`). On the control side, `src/device/kit-control-diagnostics.ts` strict-parses the firmware's retained schema-3 diagnostics snapshot (ESP WS error taxonomy, TLS errno, ring high-water, Wi-Fi reason), and `src/device/control-mount-diagnostics.ts` implements the "reconnect is evidence, not recovery" policy: an unexpected control remount still fails the run, but the replacement generation is used — under 25 s/30 s hard bounds (`:59-60`) — to read _why_ the predecessor died.

## 2. `device-pcm-proxy.ts` (931 lines) — responsibilities and assessment

Responsibilities actually present: (a) HTTP upgrade/subprotocol negotiation and bearer auth; (b) session registry keyed by session id with replace-on-reconnect (`:251-253`); (c) provider dialing; (d) per-session dual-socket relay; (e) single-flight Blob-conversion mailboxes per direction (an explicitly reasoned bound — a `.then()` chain is not a queue bound, `:313-321, 450-490`); (f) provider JSON parse/dispatch (zod loose object); (g) the PTT/text turn state machine (`#inputActive/#responseActive/#responseRequested/#suppressDownlink`); (h) the bounded downlink ring with wraparound copy; (i) two delivery modes with a media clock; (j) EOS ordering; (k) typed failure/close propagation.

**Is it doing too much?** It is cohesive — everything is "the PCM generation" — and the comment density shows each bound was bought with a physical incident. But it conflates at least three separable machines: transport/auth (fetch + subprotocol + bearer decoding), the provider turn protocol (Grok-shaped control events), and the downlink playout scheduler (ring + watermark + pacer). The session's state machine is implicit in ~12 mutable fields (`:321-334`) rather than an explicit state enum, and correctness depends on subtle cross-field invariants (e.g. suppress → clear-queue → response.created unsuppress). Two concrete consequences found by reading, not testing:

- **The turn state machine is only correct in push-to-talk mode.** `requestTextResponse` sets `#suppressDownlink = true` (`:429`), but the only code that clears it is inside `if (this.#inputMode === "push-to-talk")` on `response.created` (`:562-569`). In a `server-vad` session (the `LocalDevicePeerServer` default, `local-device-peer-server.ts:53`), a text turn suppresses all downlink audio forever, and `#responseRequested` is likewise never cleared, so every subsequent `requestTextResponse` returns `false` (`:419-425, 446`). Nothing in the current callers hits this (all deterministic runs resolve PTT sessions), but it is a loaded trap in the mode Grok VAD/StackChan will use.
- **Inconsistent admission bounds.** `maximumProviderMessageBytes` defaults to 64 KiB (`:238`) — 2 s of audio — while the downlink ring holds 5,120 bytes (8 frames). Any single provider message larger than 160 ms trips `device-downlink-queue-overflow` (`:606-609`) _even in device-clocked mode_, because the whole message is enqueued before any drain. The 64 KiB validation bound therefore admits messages the ring can never hold; the effective bound is the ring, and the larger constant is misleading.

**Mirroring firmware logic.** The session is essentially a userspace copy of the firmware downlink lane: startup reservoir ↔ the Stick's 4-descriptor/80 ms prebuffer (`firmware/platforms/iterate_m5unified/m5sticks3_direct_audio.cpp:81`), bounded ring with generation-destroying overflow ↔ the 640 ms downlink ring (`firmware/targets/m5sticks3/main/main.cpp:152-159`), underrun-as-terminal ↔ the firmware's underrun/recovery policy. In `device-clocked` mode most of that machinery degenerates to bounded pass-through and the file itself concedes the firmware owns the definitive policy (`:707-718`). `host-paced` survives as a "comparison path" yet is still the default (`:233`) — see smells.

## 3. Testing strategy — how device audio is actually verified

The strategy is a ladder from pure-host fakes to a physically independent acoustic oracle:

**Unit layer.** `device-pcm-proxy.test.ts` (24 tests, `:114-840` of the test file) drives the proxy through captun `WebSocketPair` fakes; a `StrictCloseWebSocket` enforces WS-valid close codes and a `DeferredBlob` exercises the single-flight conversion mailbox. Tests cover auth transport variants, session-ready ordering, rechunking without JSON leakage, EOS ordering, PTT commit/hold/cancel semantics, pacing, the physical endurance source (1,000-byte/31.25 ms chunks), first-underrun failure, device-clocked drain and startup lead, jitter-budget rejection, Blob bounds, and close provenance.

**Deterministic sources.** `DeterministicPcmProvider` owns one transport/pacing loop; renderers are stateful factories so signal phase survives arbitrary chunking (`deterministic-pcm-provider.ts:9-18, 27-35`). Two smart choices: provider chunks are deliberately 1,000 bytes (31.25 ms) to force the proxy's streaming reassembly (`scripts/device-e2e.ts:222-227`), and the tone is 997 Hz, not 1 kHz, because a 1 kHz tone has exactly 20 cycles per frame, making a duplicated/skipped whole frame phase-invisible (`:229-236`). The PRBS31 dual-carrier provider (`deterministic-pcm-prbs31-provider.ts` + `src/device/acoustic-prbs31-challenge.ts`) is a run-keyed watermark: every millisecond of audio carries a decodable logical identity (two LFSR-modulated carriers at 1 k/2 kHz, 16-sample chips, seed committed by SHA-256), so a microphone artifact can say _which interval_ the speaker lost — beginning, middle, or end — and detect duplicated/skipped chips and clock drift.

**Acoustic oracle.** `acoustic-tone-analysis.ts` is a firmware-independent correlator: 5 ms half-overlapping windows, coherence-gated (rejects fans/speech), robust median-level reference with a −12 dB relative floor (so a quiet coherent room copy doesn't count as playback), 2-window stable-run debounce, gap/duration/missing-tone metrics, amplitude-step dB metrics with edge context, and phase-step continuity — the phase angle is what exposes a duplicated or skipped frame whose _energy_ never changes (`:988-997`). The artifact variant is an O(1)-memory three-pass streaming analyzer (single reused read buffer + bounded histograms) with the buffered-audio bound exported as a result field so a `readFile()` refactor can't silently make endurance duration a heap multiplier (`:82-92, 319-466`). `assessAcousticToneAnalysis` returns every violated threshold with units, not a bare boolean.

**Live tunnel gate.** `public-pcm-tunnel-cadence.live.test.ts` is opt-in (`ITERATE_KIT_LIVE_TUNNEL_TEST=1`) and runs tone→proxy→real Captun tunnel→standards WebSocket. It first asserts byte-perfection (frame count, SHA-256) and then _separately_ asserts cadence under a conservative 4-frame-prebuffer receiver model (min playout lead ≥ 0, ≤ 1 compressed/late inter-frame gap) — deliberately preserving the discovered failure mode where "the tunnel produces every correct byte and EOS, yet still makes realtime playback unsafe" (`:184-251`).

**Physical orchestration.** `scripts/device-e2e.ts` composes everything: flash or verified `--no-flash` reuse (it reads the config partition over esptool and refuses a base-URL mismatch, `:411-421, 1307-1335`), tunnel or direct-LAN, control mount + capability/playback metrics subscriptions, a `DeviceRuntimeProbe` that races every wait against first failure and validates metric-envelope continuity, SoX/CoreAudio capture with monotonic capture markers used as _causal_ analysis boundaries (a marker taken before requesting the response supplies `analysisStartMs`, excluding recorder warm-start replay without cherry-picking a waveform episode, `:896-911`), an armed playback-counter tripwire so loss counters fail the run near the incident rather than at a generic timeout (`:536-553`), optional bounded control churn (real `getDiagnostics` at N Hz during playback, judged for ≥90 % applied load, `:614-685`), a physical network monitor (device/router/worker pings + diagnostics on direct LAN only — Captun hides the peer address, and they refuse to invent reachability, `:743-753`), and a network-validity artifact that can retroactively fail a _passing_ audio run (`:1036-1041`). Recovery-proof and endurance modes layer conserved-incident and ladder policies on top; endurance currently fails closed on an intentionally empty runtime adapter (`:554-574`).

**Clever vs fragile.** Clever: instrument-vs-device separation (the ffmpeg/AVFoundation recorder was itself convicted; SoX + sample-count-vs-wall-time integrity is now required); fail-closed everywhere (strict zod, refuse-to-guess network validity, empty endurance adapter); 997 Hz/PRBS31/misaligned chunks; markers as causal boundaries. Fragile: the whole physical verdict flows through a `console.log key=json` line protocol consumed by humans/agents; acceptance thresholds live inline at call sites (`:914-921`) while a second threshold home exists in `m5sticks3-playback-endurance-target.ts`; the live cadence gate's fixed SHA and ±10 ms windows are honest but environment-sensitive.

## 4. `firmware-architecture.test.ts` — invariants enforced on the firmware tree

This 694-line vitest suite is "architecture as regression tests": the host TS suite reads firmware C/C++ _source text_ (comments stripped, `:25-27`) and pins ~20 invariants, nearly all traceable to a specific physical incident documented in an adjacent comment:

- **Dependency boundaries**: `components/core` + `components/capabilities` free of M5Unified/M5Stack/esphome/device/simulator includes (`:59-84`); device profiles free of platform SDK headers (`:86-98`); the C Cap'n Web interop suite files must exist (`:41-57`).
- **Control/PCM separation**: the Cap'n Web transport cannot grow binary-frame APIs; the PCM header must declare the subprotocol and S16*LE (`:115-138`); the PCM transport is a separate socket that never touches `esp_wifi*\*` (`:216-249`); control must use the taskless bounded WebSocket wrapper, not `esp_websocket_client`(whose`stop()`joins a private task with`portMAX_DELAY` — the root of the station-outage non-recovery) (`:251-286`).
- **Concurrency/ownership**: single SPSC control-outbox consumer (`:140-169`); mailbox slot counts re-derived from parsed `constexpr` constants and rechecked against the profiled worst-case burst arithmetic (`:171-214`); atomic increment/load on every cross-task WS counter (`:288-321`); separate generation-fence vs lifecycle mailboxes so a metrics command can't erase a fence completion (`:602-656`); control pinned to core 0, audio owner to core 1 (`:466-492`); no TLS separate-TX-lock opt-in (`:494-516`).
- **Realtime discipline**: PCM wakes consumers instead of polling (`:323-340, 422-448`); handshake-era microphone audio purged via the portable generation transition before readiness (`:342-365`); peer-delivery guard wired on the real platform (`:367-420`); ring capacities expressed in milliseconds of measured stall coverage, not arbitrary counts (`:450-464`); codec-level −18 dB DAC attenuation pinned to the literal ES8311 register write (brownout fix) (`:570-600`); no serial/display I/O in the steady-state loop (`:672-682`); native tests assertion-enabled and executed by the default TS suite (`:684-693`).

This is genuinely valuable — it converts one-off physical lessons into cheap CI tripwires — but it is text matching. The suite itself documents having been bitten once: a `static void` anchor silently produced an empty slice and vacuously passed (`:394-400`). `sourceSection` now throws on missing markers, but the raw `slice(indexOf(...))` at `:677` still has the vacuous-pass shape: if `for (;;) {` were renamed, `indexOf` returns −1, `slice(-1)` yields one character, and both `not.toContain` assertions pass trivially. Same pattern at `:663-666`.

## 5. Host ↔ firmware alignment and drift risk

**Aligned concepts** (same words, same semantics): generation/epoch death-and-reconnect; bounded rings with typed overflow; freshness over replay; zero-length EOS; startup prebuffer as a _named_ policy; "socket acceptance is not peer receipt".

**Duplicated with no shared source of truth:**

- Frame geometry: 640/20 ms/16 kHz appears independently in `device-pcm-proxy` defaults via `local-device-peer-server.ts:45`, `scripts/device-e2e.ts:95-96`, the live test (`:12-13`), and `pcm_websocket.h`. The subprotocol string exists twice (`device-pcm-proxy.ts:5` vs the C macro); the architecture test only checks the C header _contains_ the literal (`firmware-architecture.test.ts:136`) — nothing cross-checks TS against C.
- Startup prebuffer is described by **three different numbers**: host default 3 frames/60 ms (`device-pcm-proxy.ts:24`), firmware 4 descriptors/80 ms (`m5sticks3_direct_audio.cpp:81`), and the live test's "4-frame receiver model" (`public-pcm-tunnel-cadence.live.test.ts:210-217`) — plus a CLI knob 1..8 (`--device-clocked-startup-frames`). In device-clocked mode the host watermark and the firmware prebuffer _stack_ (the host holds 60 ms before forwarding, then the device holds 80 ms before I²S), a latency composition documented nowhere in one place.
- Buffer vocabulary diverges: host `maximumDownlinkQueuedBytes` (jitter allowance, 160 ms) vs firmware `pcmDownlinkCapacityMilliseconds` (loss reserve, 640 ms) — deliberately different roles, but a reader must reconstruct that from two comment blocks (`device-pcm-proxy.ts:7-13` vs `main.cpp:143-152`).
- `kit-control-diagnostics.ts` strict-mirrors the firmware diagnostics struct field-for-field at `schemaVersion: 3`; any firmware field change breaks the host parse. That's _declared_ fail-closed policy (`:31-37`) and I'd keep it, but it is manual, unversioned-in-one-place duplication.
- The proxy's host-paced pacer replicates the firmware's playout clock; the codebase acknowledges this is a comparison artifact (`:69-84`) yet keeps it as the default, so the two clock implementations will co-evolve.

## 6. Candid smells and risks (file:line)

1. **Server-VAD text-turn deadlock in the proxy** — `device-pcm-proxy.ts:429` sets `#suppressDownlink` that only `:562-569` (PTT-gated) can clear; `#responseRequested` similarly never resets outside PTT. Latent audio-blackhole for the StackChan/VAD path.
2. **Admission-bound inconsistency** — `maximumProviderMessageBytes` 64 KiB (`:238`) vs an 8-frame/5,120-byte ring (`:14,147`): any provider message > 160 ms kills the generation even in device-clocked mode because enqueue precedes drain (`:606-623, 719-734`).
3. **`host-paced` is still the default delivery mode** (`:233`) despite the file's own doctrine that the device I²S peripheral is the only real clock (`:73-84`). The comment says the choice "must not become an implicit fallback", but a caller omitting the option gets the legacy clock silently.
4. **Duplicated default resolution** — `maximumDownlinkQueuedBytes`/`minimumDownlinkStartupFrames` defaults computed twice, in the constructor validation (`:147-155`) and again in `fetch` (`:222-230`); a future edit to one drifts the other.
5. **Backpressure detection is best-effort** — `#send` only checks `bufferedAmount` when the socket exposes a number (`:801-810`); on peers omitting it, egress backpressure is undetectable and the 4013 paths go dead. Preserved deliberately for `wasClean` (`:52-57`) but not for this.
6. **Bearer token in `Sec-WebSocket-Protocol`** (`:104-112`) traverses tunnel/proxy layers that routinely log negotiated protocols; similarly `xai-client-secret.<v>` (`grok-realtime-voice.ts:71-73`). Short-lived for Grok, but the project bearer is not.
7. **`grok-realtime-voice.ts:109`** closes a _failed_ setup with code 1000 (normal) — the counterpart will classify it as clean; also `session.update` is fired without awaiting any ack (`:78-106`).
8. **`runDeviceE2e` is a ~1,100-line function** (`scripts/device-e2e.ts:164-1254`) with mode branching, nested try/finally, and probe/evidence machinery in-file; the extracted `src/device/*` helpers show the right direction, but the composition root itself is at the edge of maintainability, and its evidence protocol is stringly `console.log key=json`.
9. **Threshold homes are split** — acoustic acceptance literals inline (`scripts/device-e2e.ts:914-921, 947`) vs the endurance policy module (`src/device/m5sticks3-playback-endurance-target.ts`); the same "1.5 dB / 200 ms / 0 ms gap" class of numbers has two owners.
10. **Triplicated `withTimeout`** (`scripts/device-e2e.ts:1342-1352`, `src/device/control-mount-diagnostics.ts:157-167`, plus the bespoke `waitForOpen`s in `grok-realtime-voice.ts:114-143` and the live test) — trivial, but exactly the kind of drift the codebase otherwise polices.
11. **Vacuous-pass hazards in the architecture suite** — `firmware-architecture.test.ts:677` (`slice(indexOf(...))` with no missing-marker guard) can silently weaken the steady-state-I/O check; the suite already documents one such incident (`:394-400`). Every string anchor here is a rename landmine; that's an accepted trade, but the unguarded slices are fixable.
12. **Dual analysis implementations** — the in-memory (`acoustic-tone-analysis.ts:172-305`, plus `measurePhaseContinuity`/`measureActiveAmplitudeStepsDecibels`) and streaming (`:711-892`) analyzers implement the same metric pipeline twice with an equivalence claim in comments (`:788-795`); edge-context or threshold changes must be made in both, and only test fixtures keep them honest.
13. **Prebuffer arithmetic in three places** (see §5): host default 3 frames, firmware 4 descriptors, live test's 4-frame model — no single named constant or doc composes the actual end-to-end startup latency budget.

Overall: this is an unusually disciplined host stack — bounds, failure taxonomies and evidence provenance are first-class, and the testing ladder (fakes → deterministic providers → live tunnel → acoustic/PRBS physical oracle) is the strongest part of the design. The main structural debts are the proxy's implicit turn state machine (already wrong outside PTT), the duplicated playout-clock/prebuffer logic straddling host and firmware, and the monolithic e2e composition root.
