## 1. End-to-end dataflow

**Fixed protocol shape (everywhere):** PCM v1 = mono S16LE, 16 kHz, 20 ms frames = 320 samples = 640 bytes, one frame per binary WebSocket message on a dedicated socket with subprotocol `iterate.kit.pcm.v1` (`components/core/include/iterate/kit/pcm_websocket.h:13-31`). A zero-length final binary message is the ordered downlink end-of-stream marker. The Cap'n Web control connection and the PCM connection are deliberately separate sockets (`targets/m5sticks3/main/main.cpp:52-56`, `platforms/iterate_esp_idf/pcm_transport.c:22-27`).

### Uplink (mic → network)

1. **M5Unified recorder (I2S1 RX, hardware)** → `BoundedCapture<320,16000>` keeps exactly **2 inline 640-B frame buffers** armed in M5Unified's two recorder queue slots (`platforms/common/include/iterate/kit/platforms/bounded_capture.hpp:41-47,243`). One completed startup frame is discarded to swallow mic settling transient (`platforms/iterate_m5unified/include/iterate/kit/platforms/m5unified.hpp:111`).
2. **Main/application task poll**: `app_main` loop (10 ms tick, `main.cpp:160-161,1196-1217`) → `iterate_kit_m5sticks3_poll` (`devices/m5sticks3/m5sticks3.c:186-205`) → audio module `audio_poll` (`components/core/src/audio.c:134-169`) → `M5UnifiedHalfDuplex::pollCapture` → `BoundedCapture::pump(M5.Mic, …)` (`platforms/iterate_m5unified/m5unified.cpp:360-366`). At most **one frame per poll**, and the controller enforces **at most one borrowed frame in flight** (`audio.h:43-48`, `audio.c:309-355`; overflow = `BACKPRESSURE` + drop counter, never a queue).
3. **Egress into lane**: target-supplied `sendPcm` (`main.cpp:353-425`) rejects frames while the PCM transport is not `READY`, otherwise copies the 640 B + a capture-completion timestamp into the **uplink SPSC ring** via `iterate_kit_pcm_lane_submit_uplink_at` (`components/core/src/pcm_lane.c:235-263`), then `xTaskNotifyGive`s the PCM network task. Ring: **32 slots × 648 B (8-B timestamp + 640-B frame) = 640 ms capacity** (`main.cpp:152-159,265-272`). A full ring drops the _newest_ frame and latches an **epoch-reset request** for the consumer (`pcm_lane.c:256-262`) — the consumer then purges the whole mic epoch rather than shipping stale speech.
4. **PCM network task** (`iterate-pcm-net`, core 0, prio 6): outer schedule is _receive → bounded uplink (≤4 raw writes) → receive_ (`pcm_transport.c:28-34,587-716`). Uplink is driven by the portable **conductor** (`components/core/src/pcm_uplink_conductor.c:308-522`) which per work-step: services one queued control frame (PONG/CLOSE/PING) first, polls the **peer-delivery guard**, then polls the **uplink sender**.
5. **Sender** (`components/core/src/pcm_uplink_sender.c`) read-acquires the oldest ring slot, retains it across short writes, and hands it to the sans-I/O **websocket_tx** framer (one masked 648-B wire-frame workspace, `ITERATE_KIT_WEBSOCKET_CLIENT_FRAME_BYTES(640)=648`, `websocket_frame_writer.h:15-19`; storage in `esp_idf_pcm_transport.h:174-176`). Freshness enforcement: `restart_after_no_progress_ms=500`, `maximum_frame_send_duration_ms=1000`, `maximum_capture_age_ms=250` (`esp_idf_websocket_policy.h:53-55`); breach ⇒ discard everything + RESTART (reconnect as a freshness boundary, not retransmission).
6. **Peer-delivery guard** (`components/core/src/pcm_peer_delivery_guard.c`, header `pcm_peer_delivery_guard.h:119-142`): inserts an RFC-6455 PING (`"itxp"`+generation+barrier-id, 12 B payload) after every **4** locally-accepted frames, allows at most **8 unconfirmed frames (160 ms)**, forces a barrier after **40 ms** (PTT tail), and replaces the connection after **200 ms** without matching PONG; idle probes at 2 s / 1 s timeout cover silent sockets (`esp_idf_websocket_policy.h:56-61`, with compile-time proofs of the ordering invariants at lines 81-109). This bounds PCM hidden inside opaque mbedTLS/lwIP/Wi-Fi buffers.
7. **Raw socket**: custom nonblocking WebSocket client over `esp_transport` (TLS via cert bundle), zero-timeout writes, TCP_NODELAY, keepalive as last resort (`platforms/iterate_esp_idf/websocket_connection.c:20-48`). `esp_websocket_client` is _not_ used.

### Downlink (network → speaker)

1. **PCM network task** drains ≤8 WebSocket chunks per receive burst (`pcm_transport.c:43-52,382-472`) into `iterate_kit_pcm_lane_receive_downlink_at` (`pcm_lane.c:349-486`), which reassembles TLS short-reads **directly into a write-acquired downlink ring slot** (no second reassembly buffer), stamping local receive time. Downlink ring: **32 slots × 656 B = 640 ms** (`main.cpp:153-159,269-272`). Zero-length message publishes an in-band `END_OF_STREAM` slot so completion cannot overtake queued PCM (`pcm_lane.h:49-72`).
2. `downlink_ready` callback (network task) only does `xTaskNotifyGive` to the audio owner (`pcm_transport.c:352-357`, `main.cpp:326-335`, `m5sticks3_direct_audio.cpp:407-416`).
3. **Audio owner task** (`iterate_audio`, core 1, prio 19): `taskLoop` (`platforms/iterate_m5unified/m5sticks3_direct_audio.cpp:517-604`) runs `RealtimePlayback<320,16000,4,200,200,2000>::pump` (`m5sticks3_direct_audio.hpp:103-110`): acquire frame from lane → drop if receive-to-now age > **200 ms** → `preloadMono`/`writeMono` into the exact oldest completed DMA descriptor.
4. **DirectI2sStereoOutput** duplicates mono→stereo through **one 1280-B scratch frame** (`platforms/common/include/iterate/kit/platforms/direct_i2s_stereo_output.hpp:125-160`), then **EspIdfDirectI2sBackend** (`platforms/iterate_esp_idf/include/iterate/kit/platforms/esp_idf_direct_i2s_backend.hpp`) does `i2s_channel_preload_data`/`i2s_channel_write(timeout=0)` into **4 DMA descriptors × 1280 B = 80 ms** of physical reserve.
5. **I2S hardware**: the speaker path uses the **new ESP-IDF `i2s_channel` API** (`i2s_new_channel`, `i2s_channel_init_std_mode`, `i2s_channel_register_event_callback`, `driver/i2s_std.h`) on I2S0 TX, MCLK×128, GPIO 18/17/15/14, `auto_clear_before_cb=true` so a missed refill plays silence instead of stale speech (`m5sticks3_direct_audio.cpp:92-122`). The on-sent ISR (IRAM) timestamps EOF, publishes descriptor identity into a 4-entry SPSC completion ring, and wakes the owner (`esp_idf_direct_i2s_backend.hpp:470-533`). ES8311 codec is configured directly over I2C with a **fixed −18 dB DAC ceiling** (reg 0x32=0x9B) as brownout protection (`m5sticks3_direct_audio.cpp:22-42,336-366`); the power amp is a latch on M5PM1 GPIO3 (`:310-333`).
6. **Prebuffer/underrun policy** (`realtime_playback.hpp`): playback starts only when all 4 descriptors hold content (`:802-813`); a partial prebuffer older than 200 ms is destroyed; EOS pads remaining descriptors with silence and stops cleanly at final content EOF (`:652-700`); underrun writes one bounded silence descriptor, drops exactly the late stale frames with scalar debt, and re-enters buffering; any driver-queue overflow or refill-lead miss (<2 ms) **poisons the generation** and destructively resets the channel.

**Reconnect/generation fencing (both directions):** on socket replacement the conductor purges ring + tx workspace + pong namespace (`pcm_uplink_conductor.c:221-286`); the transport closes the socket to kill opaque TLS bytes; downlink admission stays closed until the audio owner completes a physical `flushGeneration` fence (stop DMA, delete channel, purge lane) acknowledged via a non-blocking mailbox poll (`pcm_transport.c:853-935`, `esp_idf_pcm_transport.h:206-218`, `m5sticks3_direct_audio.cpp:464-499,606-650`).

## 2. Task model

| Task              | Core  | Prio            | Stack                                                              | Owns                                                                                                                                                                              |
| ----------------- | ----- | --------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app_main` (main) | 0     | 1 (IDF default) | IDF default                                                        | M5.update/button/display, device events, Cap'n Web dispatch, **capture pump**, control+PCM transport `poll()` reconciliation, metrics sampling; 10 ms loop (`main.cpp:1196-1348`) |
| control net task  | 0     | **5**           | 8192 B static                                                      | Cap'n Web WebSocket (`itx_transport.c:1135-1143`)                                                                                                                                 |
| `iterate-pcm-net` | 0     | **6**           | 8192 B static (= TLS owner stack, `esp_idf_pcm_transport.h:35-37`) | PCM socket, conductor, downlink receive (`pcm_transport.c:825-851`, core pin `:71`)                                                                                               |
| `iterate_audio`   | **1** | **19**          | 8192 B static                                                      | All playback policy, I2S channel lifecycle, codec/amp I2C (`m5sticks3_direct_audio.hpp:127-134,171-172`)                                                                          |
| I2S TX ISR        | 1     | ISR             | —                                                                  | EOF timestamp + SPSC publish + owner notify, IRAM (`esp_idf_direct_i2s_backend.hpp:453-533`)                                                                                      |

PCM gets one priority level above control by design, with a compile-time proof (`esp_idf_websocket_policy.h:36-70`). Fairness quanta instead of priority games: 8 receive chunks / 4 raw writes per pass; `PROGRESS` re-polls with 0-tick wait; `IDLE/DEFERRED` sleeps 1 tick (10 ms at the 100 Hz tick) — encoded portably in `iterate_kit_esp_idf_pcm_network_wait_ticks` (`esp_idf_websocket_policy.h:124-137`).

**Starvation analysis:** playback cannot be starved by network (own core, prio 19; network only feeds the lane). The real exposure is the reverse asymmetry: **capture runs on the priority-1 main task on core 0**, _below_ both network tasks and Wi-Fi/lwIP. With only 2×20 ms of hardware capture buffering (`bounded_capture.hpp:47`), any >~40 ms main-task stall (TLS handshake burst on core 0, display SPI in `showStatus` `m5unified.cpp:195-223`, a slow metrics sample — see §8.5) drops mic frames. Physical evidence so far is good (222 frames, 0 drops, `apps/kit/docs/physical-device-voice-goal.md:340-342`), but the margin is structural, not proven.

Callbacks vs tasks: ISR does only timestamp+publish+notify; network callbacks never copy PCM or touch speaker hardware (`main.cpp:326-335`); no audio callback does DNS/TLS/logging/allocation (`pcm_transport.c:15-20`).

## 3. Duplex vs PTT; VAD/AEC/AGC/NS; AEC reference path

- The core controller has two modes: `PUSH_TO_TALK` and `FULL_DUPLEX_AEC` (`audio.h:15-19`). M5StickS3 is strictly half-duplex PTT (`m5unified.hpp:19-28`): press ⇒ `interrupt_playback` (stop + flush _always_, even pre-first-frame, `audio.c:236-273`) then `start_capture`; the platform maps stop/flush to a **synchronous destructive fence** on the audio owner — amp off, `i2s_channel_disable`, **`i2s_del_channel`** (deletion, not disable, is the pin-ownership boundary because the mic reuses MCLK/BCLK/WS on I2S1: `m5sticks3_direct_audio.cpp:169-193`, `m5unified.cpp:297-341`) — then `M5.Mic.begin()`. While suspended, the owner continuously discards downlink (`m5sticks3_direct_audio.cpp:570-579`).
- Physical button and remote `pushToTalk.start/stop` RPC go through the **same bounded device-event queue** (`components/capabilities/src/push_to_talk.c:7-13`, `devices/m5sticks3/m5sticks3.c:41-62`, `main.cpp:1219-1237`) — no second audio path.
- **There is no VAD, AEC, AGC, or NS anywhere on the device.** Server-side VAD is disabled for the Stick (`turn_detection: null`, commit on release — proxy side; `physical-device-voice-goal.md:174-177`). The only DSP-adjacent processing is the fixed codec attenuation and mono→stereo duplication.
- **AEC readiness:** the seams exist but no reference path does. Full-duplex mode intentionally keeps capture running so "platform AEC receives a continuous microphone/reference timeline" (`audio.c:20-23`), and every downlink frame carries receive timestamp + per-descriptor EOF timestamps in the same monotonic domain (`realtime_playback.hpp:83-99`) — so a reference tap at `DirectI2sStereoOutput::writeMono` (mono frame + eofAtUs) is feasible and well-timed. Nothing routes output PCM toward the capture side today, and the StackChan (full-duplex/AEC) target has only a control-plane simulator (`simulator/devices/stackchan.cpp` has no audio at all).

## 4. Buffer management

- **Single buffering boundary per direction**: the SPSC lane is deliberately the _only_ application PCM FIFO (`pcm_lane.c:6-17`); every other layer holds at most one frame (capture 2 hardware slots, sender 1 retained slot, tx 1 masked wire frame, playback 1 borrowed frame + 1 stereo scratch, DMA 4 descriptors). No allocation anywhere on the hot path; all storage static in `Runtime` (`main.cpp:222-307`) or IDF-owned DMA.
- **SPSC ring** (`components/core/src/spsc_ring.c`): lock-free acquire/publish/release with release/acquire fences, power-of-two slots, no waiting; full ⇒ `BACKPRESSURE`, empty ⇒ `UNAVAILABLE`; policy meaning belongs to higher layers (`:21-27`).
- **Backpressure semantics**: uplink full ⇒ drop-newest + epoch-reset request (whole mic epoch purged by consumer) (`pcm_lane.c:18-25,256-262`); downlink full ⇒ the transport treats it as ordered-item loss and **restarts the whole socket generation** rather than tearing a hole mid-speech (`pcm_transport.c:323-343`). Underrun ⇒ bounded silence descriptor + exact-late-frame drop + same-generation resume; overflow of IDF's private finished-pointer queue ⇒ poisoned generation + destructive reset (`esp_idf_direct_i2s_backend.hpp:201-279`, `realtime_playback.hpp:826-895`).
- **PSRAM vs internal RAM**: the audio path uses **no PSRAM** — everything is static internal RAM (lanes ≈ 41 KB payload+metadata, DMA 5,120 B allocated by IDF from internal DMA-capable heap, stereo scratch 1,280 B, capture 1,280 B, 3×8 KB static task stacks). PSRAM and DMA-capable heap are separately _reported_ (`m5unified.cpp:267-275`, `main.cpp:774-797`); the resource profile keeps each class distinct precisely so a hidden FIFO can't sneak in (`simulator/resource_profile.cpp:423-489`).
- **Buffer telemetry honesty** is a first-class concept: `buffer_metrics.h:27-32` defines OBSERVED / DERIVED_BOUND / CAPACITY_ONLY / UNAVAILABLE, and the transport reports the full egress chain including explicitly-unavailable TLS/Wi-Fi layers and capacity-only lwIP (`pcm_transport.c:1090-1163`).

## 5. Configuration plumbing

Effectively everything is **compile-time, per-target constants** — nothing is runtime-configurable:

- Wire shape: enum constants in `pcm_websocket.h:16-31`.
- Lane capacities (640 ms each way): `main.cpp:143-159` (target file).
- Network/freshness/peer policy: one shared header `esp_idf_websocket_policy.h:36-63`, with **compile-time negative-array proofs** of cross-constant ordering (barrier < confirmation < capture-age; idle probe bounded ≤5 s) (`:66-109`).
- Playback policy: template parameters (`MaximumFrameAgeMs=200`, `PartialPrebufferTimeoutMs=200`, `MinimumRefillLeadUs=2000`) and descriptor geometry (`descriptorCount=4`) in `m5sticks3_direct_audio.hpp:33-37,103-110`.
- Gain: fixed codec ceiling −18 dB hardcoded in `m5sticks3_direct_audio.cpp:37-42` (board power policy).
- Mic startup discard: `m5unified.hpp:111`; capture double-buffer count: `bounded_capture.hpp:47`.

The goal doc demands "explicit tuning knobs with defaults, bounds, and metrics" (`physical-device-voice-goal.md:196-199`); the current answer is "named constants with proofs and metrics" — good bounds/metrics, but knobs are not per-device data, they are per-target code. A second board must instantiate new templates/constants (which is the stated intent), but there is no config-partition or provisioning-time path for any audio parameter.

## 6. Layering and coupling

Largely exemplary. The dependency direction is: core (C, sans-I/O) ← platform common (header-only C++ templates) ← ESP-IDF/M5Unified adapters ← target composition root.

- Audio core knows nothing of sockets: `audio.c` sees only injected `hardware`/`egress`/`capture` function tables (`audio.h:35-86`). PCM ordering policy (control-before-data, partial-write atomicity, epoch purge) lives in the portable conductor precisely so ESP glue can't reorder it (`pcm_uplink_conductor.c:6-24`, `pcm_transport.c:775-780`).
- Physical PCM I/O is pluggable at three seams: audio hardware/capture driver structs (device-agnostic), `RealtimePlayback`'s `Driver` template, and the backend's `I2sOps`/`BoardOps` injection (`esp_idf_direct_i2s_backend.hpp:44-56`).
- Genuine (small) violations/warts:
  - **Core audio includes Cap'n Web**: `audio.h` includes `peer.h`, and `audio.c` returns `CAPNWEB_OK` inside `iterate_kit_poll_result` (`audio.c:138-141,173-176`). The lifecycle controller is coupled to the RPC framework's status type solely to be a peer module.
  - **Target reads transport struct internals**: `sendPcm` gates on `state.pcmTransport.state` directly (`main.cpp:368-384`) instead of an accessor; safe only by the documented single-task convention.
  - **Platform reaches into conductor internals**: `report_uplink_recovery` reads `transport->uplink.sender.restart_incidents` directly before calling the metrics API (`pcm_transport.c:494-497`).
  - Policy constants for the _portable_ conductor live in a **platform** header (`esp_idf_websocket_policy.h`) — acceptable as platform tuning, but the PCM/control task-priority relationship asserted there is policy that a second platform must re-derive.

## 7. Host-testable vs device-only; simulator quality

- **Host-tested (deterministic, virtual-clock):** spsc ring, lane, uplink sender, conductor, peer guard, websocket tx/framer, audio controller (`tests/pcm_lane_test.c`, `pcm_uplink_sender_test.c` 597 L, `pcm_uplink_conductor_test.c` 1190 L, `pcm_peer_delivery_guard_test.c`, `audio_controller_test.c`); a sans-I/O **fault harness** drives the sender through would-block/trickle/disconnect link modes on a virtual clock (`tests/pcm_realtime_fault_harness_test.c:26-40`); `BoundedCapture` against a fake recorder (`bounded_capture_test.cpp`); the whole playback stack — `realtime_playback_test.cpp` (1989 L) and `direct_i2s_stereo_output_test.cpp` (1104 L) model **descriptor identity** (0/1/2/3), not just counts, so a count-only fake can't hide an identity bug (`realtime_playback.hpp:47-60`); even the ESP transport shell runs on host against fake ESP-IDF/WebSocket headers including a generation-barrier that returns `UNAVAILABLE` first (`tests/esp_idf_pcm_transport_test.c:62-81`).
- **Device-only:** real i2s_channel driver behavior/ISR timing, M5.Mic, ES8311/amp I2C, TLS/Wi-Fi behavior, actual scheduling, and acoustics (the docs are explicit that "DMA completed" is not "audible"; the external mic rig closes that gap, `realtime_playback.hpp:107-113`, doc `:289-312`). The build has a post-link "realtime audit" (IRAM placement of atomics etc., `esp_idf_direct_i2s_backend.hpp:73-88`).
- **Simulator (`simulator/devices/m5sticks3.cpp`)** is deliberately a _control-plane_ model: real device profile + Cap'n Web + PTT ordering + audio-controller ownership/backpressure, with capture injected via `__test.submitCapture` and completion held until `__test.completeCapture`; it explicitly refuses to imitate I2S/DMA/task priorities/sound (`:10-23,154-165`). Metrics are labeled wire-contract fixtures, radio evidence honestly absent (`simulator/src/hardware.cpp:44-122`). This honesty is a strength; the corresponding gap is that no host artifact exercises audio _timing_ end-to-end — that burden is on the per-layer virtual-clock tests plus the physical rig.

## 8. Candid smells / risks

1. **Uplink capture is the priority orphan.** Downlink got a dedicated core-1 prio-19 owner; capture is pumped from the prio-1 main task on core 0 under both network tasks, with only 40 ms of hardware buffer (`main.cpp:1196-1217`, `bounded_capture.hpp:47`). Any main-loop stall >40 ms silently gaps the mic. The drops are at least counted (`audio.c:326-329`).
2. **Metrics sampling can block the main task for up to 1 s on a wedged audio owner.** `sampleRuntimeMetrics` → `playbackMetrics()` → `runBoundedCommand(snapshotMetrics)` is a synchronous rendezvous with the prio-19 owner, timeout 1000 ms (`main.cpp:482`, `m5sticks3_direct_audio.cpp:431-444,698-754`, `commandAcknowledgementMs` `m5sticks3_direct_audio.hpp:173`). Once per second in steady state, but a wedged owner converts diagnostics into a 1 s main-loop stall — which then also starves capture (smell 1 compounds).
3. **PTT press is a synchronous cross-task hardware fence on the main task** (amp off → i2s_del_channel → Mic.begin), bounded at 1 s (`m5unified.cpp:297-327`, `m5sticks3_direct_audio.cpp:698-754`). Correct for half-duplex pin sharing, but the button-to-capture latency budget depends on I2C + channel deletion latency and is unmeasured as a first-class metric.
4. **Two consumers can touch the downlink SPSC consumer side.** The main task runs `iterate_kit_pcm_lane_discard_downlink` after a generation barrier (`pcm_transport.c:899-905`), while the audio owner is the normal consumer and, when suspended, also discards on every wake (`m5sticks3_direct_audio.cpp:570-579`). Safety currently rests on the receive-admission gate keeping the ring empty during the main-task purge; formally, `read_acquired`/`read_index` are non-atomic single-consumer state (`spsc_ring.c:41-57`) and this is an SPSC contract bend that only ordering conventions protect.
5. **`audio.c` ↔ Cap'n Web coupling** (`audio.c:138-141`): the portable audio lifecycle cannot be reused without dragging in `capnweb.h`.
6. **Copy-pasted atomics helpers** in ≥5 files (`spsc_ring.c:29-67`, `pcm_lane.c:45-102`, `pcm_uplink_sender.c:21-55`, `pcm_uplink_conductor.c:26-59`, `pcm_transport.c:76-115`) while `iterate/kit/atomic.h` exists and is used only by `websocket_connection.c`. Divergence risk in exactly the code where memory-order subtleties matter.
7. **Dead production code**: `bounded_playback.hpp` (the older M5Unified-Speaker pump) is referenced only by its own test (`tests/bounded_playback_test.cpp`) — superseded by `RealtimePlayback` but still maintained.
8. **Receive discovery is tick-polled.** The PCM task's 1-tick (10 ms) idle wait is the only downlink wakeup source; the code itself flags "until receive readiness is moved to a socket-driven wakeup" (`pcm_transport.c:598-611`). Adds up to 10 ms jitter per frame into a 4-descriptor/200-ms-age playback budget.
9. **8 KB stacks under TLS.** Both network tasks share the 8192-B "TLS owner" stack constant (`esp_idf_websocket_connection.h:43`, `esp_idf_pcm_transport.h:35-37`) with only a 512-B pre-connect floor check (`pcm_transport.c:630-635`); mbedTLS handshake depth variance across IDF/config bumps is a known way to brown this out. Mitigated by high-water telemetry.
10. **IRAM is one byte from full** on the linked image (16,383/16,384 used, `apps/kit/docs/physical-device-voice-goal.md:352-354`) — any added IRAM_ATTR (e.g., more ISR code for an AEC tap) will not link.
11. **The −18 dB brownout fix is uncommitted working-tree state** (`m5sticks3_direct_audio.cpp:37-42` is in the git-status modified set) — a physical-safety policy that currently exists only on this branch's dirty tree.
12. **No runtime tuning surface** (§5): every "tuning knob" the goal doc requires is a recompile; per-device experimentation (descriptor count, freshness windows, gain) can't be done from provisioning or RPC.
13. **Timestamp provenance**: capture timestamps are taken at lane submission on the main task, not at the I2S sample clock (`main.cpp:389-402`, admitted in-line) — capture-side scheduling delay is invisible inside "capture age", which matters once uplink latency budgets tighten or AEC needs sample-accurate alignment.

**Overall:** this is an unusually disciplined embedded audio architecture — sans-I/O cores with fault harnesses, single-owner tasks, explicit freshness-over-throughput policy, honest telemetry taxonomy, in-band EOS, generation fencing down to physical DMA, and every buffer bounded and accounted. The dominant structural risk is the asymmetry between the pampered downlink (dedicated core/priority) and the uplink capture path living on the weakest task in the system; the second tier is the handful of single-owner conventions (transport-state read, dual downlink discarder, mailbox timeouts) that are documented rather than mechanically enforced.
