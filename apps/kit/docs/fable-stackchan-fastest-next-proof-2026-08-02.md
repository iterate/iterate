# Fable review: fastest production-shaped path to a proven StackChan Grok turn — 2026-08-02

Read-only review at `c-capabilities` @ `f3fd29243`. Sources: first-hand reads of the HEAD firmware (`apps/kit/firmware`), userspace config worker, harness, and evidence bundles; the prior-art checkout `~/src/github.com/iterate/stackchan` (code **and** its retained physical measurements); vendored esp-sr 2.4.7 / esp_codec_dev / patched CoreS3 BSP; `targets/stackchan/sdkconfig`; and the prior Fable reports of 2026-07-31/08-01. No source, hardware, or deployment was touched; only this file was created. Claims are labelled **C** (confirmed by reading code/evidence), **M** (physical measurement in a retained artifact), **H** (hypothesis).

## Executive verdict

The 2026-08-01 review checklists are largely **already landed at HEAD**, and their central hypothesis — "uplink ≈12 dB too quiet" — was **refuted by the instrumentation those reviews prescribed**: the now-exported AEC signal windows measured device clean peaks of 9,767–13,929 across the 17:25–17:39 runs, _louder_ than prior art's proven-working ≈−16 dBFS (~5,000) delivery point (M). Nothing in slot mapping, gain, AEC configuration, wire format, or memory blocks a real turn today: the 2026-08-01T17:31 run already passed the AEC gate (5.97 dB suppression, near-end preserved), physically played Grok speech through the StackChan speaker, and completed one server-VAD turn end-to-end (M). Every failure since is operational, and ranked: (1) the StackChan project still runs the **pre-fix userspace** whose subscription defect (7/7 failures observed on the 17:39 probe) breaks the interruption/metrics plane — the fix at HEAD is deployed only to the Stick project; (2) the **physical network position is measured invalid** (−67 dBm, 61–78 ms router RTT, ~2 s coverage gaps), which simultaneously fails the network gate, drops uplink audio mid-utterance, and best explains the truncated "Reply exactly." transcript; (3) the harness's **all-or-nothing verdict** erases a green turn whenever the later barge-in phase times out, which is where all three runs died; (4) the **echo-margin/VAD-sensitivity tension**: threshold is now at the 0.1 floor while measured echo suppression is ~6 dB — prior art self-triggered on its own echo even at 19.2 dB ERLE (M) — and the still-open B2 path (interrupt-while-one-is-pending → device error → worker `close(4000)`) turns any echo-double-trigger into session death. The fastest route is therefore not DSP work: deploy the fixed userspace to the StackChan project, reflash once at HEAD (porting the watchdog/TLS-internal-RAM settings that commit `b2d15aa0f` gave only Waveshare), pre-gate the network, split the harness so a passing turn is committed before barge-in is attempted, and only then measure echo margin and fix B2 before the barge-in leg. The firmware architecture is **not** in the prior-art local maximum — its three fatal defects (16 s playout queues, blocking TLS on the mic-drain task, silent clean-buffer drops) are all structurally absent at HEAD; the current local maximum is the **proof harness and run conditions**, not the audio stack.

## 3. Blockers that truly prevent a real StackChan Grok turn (ranked)

- **T1 — The StackChan project runs the pre-fix userspace** (C). `DeviceSubscriptionCoordinator` (`device-subscriptions.ts`, worker.ts wiring, test) exists only at HEAD and was applied to the _Stick_ project (`kit--kit-stick-voice-e2e-20260731`); the StackChan project `prj_0363ecd5…` has no post-fix install evidence, and the 17:39 probe shows the defect live there (7/7). Without the event/metrics planes, the barge-in acknowledgement path and mid-run metrics are unreliable. Remedy: `install-userspace-worker.ts` against the StackChan project (13-file allow-list already includes `device-subscriptions.ts`) — **no reflash required**.
- **T2 — Network position is measured invalid and corrupts the audio it carries** (C for the measurements; strong **H** for utterance truncation). −67 dBm, RTT over budget, 2 s coverage gaps → the same run shows +125 uplink drops and 4 freshness restarts mid-utterance; a 1.1 s detected-speech window from a ~4 s prompt is exactly what freshness-purged uplink looks like. The verdict formula requires `network === "valid"` (`prove-production-stackchan-grok.ts:670`), so **no run at this position can pass regardless of any code change**. Remedy: move device/AP or pick a clean interval; pre-gate before burning runs (route step 3).
- **T3 — Harness phase structure erases green turns** (C). All three runs threw `"Timed out waiting for the long Grok response to become physically active before barge-in"` (`production-pcm-generation.ts:225` via `prove-production-stackchan-grok.ts:384`, 90 s budget) — after the turn evidence had been collected. `manifest.json` is written only when _everything_ passed (`:676`). One timeout in the most fragile phase discards proof of the phases that worked. Remedy: §4 D1.
- **T4 — Echo margin vs VAD sensitivity at threshold 0.1, compounded by B2** (components **C/M**, chain **H**). Measured suppression is ~6 dB; prior art measured self-triggering **even at 19.2 dB ERLE / 58.6 dB projection reduction** (`bounded-aec-assessment/assessment.json`: the clean channel still transcribed the assistant's own phrase) and at 24 dB analog gain its raw mic **saturated (32,768) during playback**. Kit runs the same 24 dB, the same volume-100 curve (+15 dB PA), and a _more_ sensitive threshold than prior art ever used. Observed: one echo-triggered turn at 17:25. The chain to session death: echo `speech_started` → interruption while a previous one is pending → device replies error (`conversation.c:109-113`) → worker `close(4000)`. The worker's re-entrancy guard (`pcm-proxy.ts:768`) only suppresses re-fire _within_ one speech burst; an echo `stopped→started` cycle re-fires. Remedies are ordered in §6 — measure first, then either raise threshold or fix margin; fix B2 before the barge-in leg regardless.
- **T5 — No watchdog and default TLS internal-RAM reserve on StackChan** (C for the gap; **H** for attribution). Commit `b2d15aa0f` ("hardware watchdog + stop starving TLS of internal RAM") touched **only Waveshare**. StackChan: TWDT 5 s with `PANIC` off and idle-tasks-only (`targets/stackchan/sdkconfig:1316-1319`), no `esp_task_wdt_add` anywhere, default `SPIRAM_MALLOC_RESERVE_INTERNAL` (32,768 vs Waveshare's 98,304) with `ALWAYSINTERNAL=4096` forcing mbedTLS handshake scratch internal. The observed `pcmLastEspTlsError 32776` and 1006 closes are consistent with, not proof of, internal-RAM pressure. A wedged StackChan currently sits there; the io-task fail-closed state (`vTaskSuspend`, `core_s3_audio_owner.c:964-972`) explicitly assumes "a higher layer may reboot", and none exists.

Explicit non-blockers (stop spending on them): uplink level and gain staging (N1: clean peaks 9.8k–13.9k ≥ prior art's proven ~5k delivery point; per-utterance level is the open sliver, §6 M2), TDM slot mapping (twice measurement-proven), esp-sr config (identical to prior art's best: FD, filter 4, NLP 2, 512-chunk assert), wire format/model pin (`grok-voice-think-fast-2.0` explicit at `providers.ts:360`, unlike prior art's drifting `grok-voice-latest`), DIRAM (HEAD moved the 128 KiB control rings to PSRAM, `main.c:133-138`; needs one re-link to confirm headroom — the checked-in StackChan ELF is stale, built 05:09 vs sources 17:25).

## 4. Deletions / refactors / harness changes that shorten time-to-proof

1. **D1 — Split the proof into committable phases** (highest leverage, harness-only). Write the turn-phase manifest (greeting + N VAD turns + AEC windows + conservation) _before_ entering the barge-in phase, then run barge-in as its own phase with its own verdict — or add `--skip-barge-in`. Today `prove-production-stackchan-grok.ts:384,676` makes barge-in a precondition for retaining any proof. This converts the current "3 failures" into "1 pass + 1 open item" at zero firmware risk.
2. **D2 — Make `interruptPlayback` idempotent while pending** (small firmware change, closes B2): treat a request that arrives while one is in flight as joining the pending purge (reply `true` on the same token's completion) instead of `"already pending"` error, `conversation.c:109-113`. The worker keeps single-flight semantics; this removes the echo-double-trigger → `close(4000)` chain. Alternative worker-only mitigation (weaker): serialize interruptions and swallow the already-pending error — but the device-side fix is ~10 lines and testable in the existing host suite.
3. **D3 — Port the Waveshare watchdog + TLS-reserve stanza to `targets/stackchan/sdkconfig.defaults`** (4 lines: `ESP_TASK_WDT_TIMEOUT_S=20`, `ESP_TASK_WDT_PANIC=y`, app-task subscription in `main.c`, `SPIRAM_MALLOC_RESERVE_INTERNAL=98304`) and ride the reflash that step 2 of the route needs anyway.
4. **D4 — One canonical invocation.** There is no `pnpm` alias for the StackChan proof; the working command shape lives only inside old `failure.json` provenance. Add `"prove:stackchan"` to `apps/kit/package.json` with the defaults that worked (port, MAC is already hardcoded, build dir).
5. **D5 — Delete/correct dead weight while touching files anyway** (not gating): the unreachable duplicate PTT-reject arm (`devices/stackchan/stackchan.c:84-85`), the three stale comments listed in §1, and — with the next firmware touch — interval slot peaks + export.
6. **Do not do now:** mode-constant collapse, `voicelab_stream` removal, `pcm_playback_interruption`/fence merge, stride change, remote gain knobs, any new metrics transport (the `pcmMetrics()` single-handle contract works and is documented in the harness at `prove-production-stackchan-grok.ts:98-109`), any porting of the Stick's debt/catch-up playback machinery to CoreS3 (`pcm_clock_playback` deliberately has no debt concept; freshness + fences already bound delay).

## 6. What must be measured before changing any DSP (all readable with existing exports)

The instrumentation the 08-01 review demanded now exists — use it before touching NLP, filter length, gain, threshold, or volume. On one **network-valid** run:

- **M1 — Far-end-only window (the greeting).** Per-second `aec_detail`: `clean_mean_absolute / near_mean_absolute` (echo suppression), and `near_peak` — if `near_peak` pegs at 32,767 during playback (prior art did, at the same 24 dB/volume-100), the echo path is clipped-nonlinear and **no AEC setting will fix it**; the correct lever is speaker volume or analog gain, not NLP.
- **M2 — Near-end-only window (the scripted prompt, speaker idle).** Per-second `clean_mean_absolute` continuity across the utterance (were there holes?), `devicePcmPeak/Rms` deltas per phase (they are session-cumulative — difference the snapshots, the harness already does), provider transcription completeness. This closes the last sliver of the level question at per-utterance granularity.
- **M3 — Echo-trigger census.** Correlate every provider `speech_started` timestamp with downlink-active intervals (both already in the evidence stream). Zero echo-coincident triggers over ≥60 s of playback at the current threshold is the gate for keeping 0.1; otherwise raise stepwise (0.15/0.2 — worker redeploy, no reflash) toward the highest value that still detects M2's real speech.
- **M4 — Transport health floor.** `uplinkFrames ≈ 50/s` sustained while speaking, `in_place_freshness_recoveries ≈ 0`, `socket_restarts = 0`. Any DSP conclusion drawn from a run violating this is void — this is exactly how the threshold walk's earlier conclusions got contaminated (**H** but strongly indicated by 17:25/17:31 counters).
- **M5 — Barge-in latency budget** (before/after D2): `speech_started` → device ack (`playbackInterruptionsCompleted`) → `last_receive_to_render_ms` drop, target ≲300 ms end-to-end (prior art measured 295 ms speech-end→playout on its good runs).

Decision fork after measurement — exactly one of: (a) M1 ratio ≪ 1 and M3 clean → keep everything, proceed; (b) M3 shows echo triggers with unclipped near — raise threshold first (provider-owned, cheapest), NLP/filter only if threshold exhausts; (c) M1 shows near clipping — reduce `speaker_volume_percent` (or add the prior-art +8 dB playback-leveler pattern later), re-measure; (d) M2 shows genuinely quiet/holey speech with clean transport — only then revisit digital gain, with prior art's soft-knee limiter (`speech_leveler.c`, knee −0.9 dBFS, table capped at 12 dB, **silent no-op above 12** — port with that trap fixed) rather than a bare multiply.

## 7. The route (stop/go gates; unattended where marked)

1. **Deploy HEAD userspace to the StackChan project** (`install-userspace-worker.ts`, no reflash; unattended). Gate: `pcmMetrics().deviceSubscriptions = {1,0,true,1,0,true}` after a `conversation.start`; greeting audible. Stop if subscriptions still fail — that is a new defect, not environment.
2. **Rebuild + reflash StackChan once at HEAD**, carrying D3 (watchdog + TLS reserve) and optionally D5 (unattended given the serial/PSU setup already scripted). Gate: boot log shows `AEC=512`, the 64×fs verify, the measured-mapping line; re-linked DIRAM headroom recorded.
3. **Network pre-gate at the physical position** (unattended): run the interval monitor standalone until a 3-minute window passes the same budgets the verdict uses (RTT ≤50 ms, no coverage gaps). Stop: if −67 dBm cannot produce a valid window, move the device or AP **before** any further runs — nothing downstream can pass (T2), and DSP data collected here is void (M4).
4. **Turn-proof run with D1** (split harness; unattended): greeting + two scripted VAD turns, no barge-in. Gates: exact STT match on prompt and reply, `digital` conservation clean mid-run, AEC gate ≥ its 3 dB floor, network valid → **commit the manifest**. This is the "real StackChan Grok turn" milestone.
5. **Echo-margin readout from the same run** (M1–M4; no code change). Gate: fork (a) → continue; (b)/(c)/(d) → apply the single selected lever, repeat step 4.
6. **Land D2 (idempotent interrupt + worker ack deadline), host-test it, redeploy/reflash as needed**, then run the **barge-in leg**. Gates: `providerResponsesCancelled ≥ 1`, `playbackInterruptions` completed, audible speech stops ≤300 ms (M5), session survives, no echo-restart loop.
7. **10-minute endurance at the same position** (unattended). Gates: zero socket restarts and freshness recoveries, flat heap, flat `last_receive_to_render_ms` (no accumulating delay — the goal-doc acceptance property), AEC windows steady.
8. **AEC quality ladder toward the 12 dB targets** (`stackchan-portability-notes:104-114`; shipped gate is 3 dB at `stackchan-aec-assessment.ts:75-83`): scripted far/near/double-talk phases in the harness — port the prior-art `aec_lab.py` protocol (three-phase, semantic gate, self-testing analyzer) onto the kit's signal windows + acoustic capture. This is the "measured AEC" completion, deliberately **after** the first proven turn.

Steps 1–5 require no DSP change and no new abstraction; only step 6 touches firmware behavior (bounded, host-testable), and step 8 is where DSP tuning is allowed to begin.

## 8. Local maxima and needless abstraction

- **The active local maximum is the harness, not the firmware.** An all-or-nothing verdict with barge-in as the last precondition means the project has been iterating provider policy (threshold 0.85→0.1) against runs that were structurally unable to pass and partially invalidated by network conditions — a textbook trap. D1 + the step-3 pre-gate break it.
- **Threshold 0.1 is itself a provisional local maximum**: it maximizes VAD sensitivity to compensate for symptoms whose causes (transport holes, echo margin) are now separately measurable. Expect the measured endpoint to be a _higher_ threshold plus either better placement or one margin lever — not the floor.
- **The firmware avoided the prior-art maximum.** The three defects that degraded prior art — 16 s of standing playout queue with newest-drop overflow, 5 s blocking TLS sends on the mic-drain task, silent 200 ms clean-buffer drops — are all structurally absent (640 ms rings + freshness discard + escalation; dedicated net tasks with nonblocking sockets; every drop counted and exported). Do not re-import prior-art buffering under any banner; reuse only its measurement assets (§6, step 8) and its hardware constants (already adopted).
- **No needless abstraction found on the critical path.** `pcm_playback_interruption` wrapping a private fence is one layer thicker than strictly needed but is small, tested, and correct — merge post-proof as already planned. The one abstraction to _refuse_: any shared "DSP framework" or device-generic AEC layer for HAVPE — the HAVPE seam (XMOS hardware AEC behind the same owner interface) survives precisely because the DSPs stay device-specific.
