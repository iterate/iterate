## Executive verdict (five sentences)

The slot-order question is now closed to datasheet standard: in the exact mode this firmware programs (`ES7210_SDP_INTERFACE2_REG12 = 0x02`, TDM I²S), the ES7210 datasheet's Figure 2e places **Channels 1 and 3 in the LRCK-low half and 2 and 4 in the high half** — wire order **MIC1, MIC3, MIC2, MIC4** — and the on-board dose-response agrees: the 18 dB mask-2 trial moved slot 1 by a uniform, twice-replicated **+7.3 dB** (`referenceMeanAbsolute` 552→1294 far-tone, 434→1006 PRBS, 355→824 speech-shaped) while the later mask-1 extension moved it by **≈0 dB** (06-02 partial run), so slot 1 = MIC3 = the speaker divider, the "slots follow selection order, so slot 1 = MIC2" suspicion is refuted, and what actually failed is that the analog PGA is a **compressed lever** on this input (0.41 dB realized per dB requested; ADC rail-clipping is excluded — post-trial reference peaks reach only 3 387 of 32 767). The reference still sits 9–18 dB below the echo the near microphone sees (17–27 dB before the trial — almost exactly the kit's own 24-vs-0 dB PGA asymmetry), and that matters because ESP-SR's FD engine contains **no double-talk detector and no delay estimator** (binary-proven; the VOIP engine in the same library has both) and its documented contract expects `refdata` to be playback-scale audio "sent to the speaker": driven this far outside that regime the **linear stage diverges on broadband** — clean output _exceeds_ near input on PRBS (mean-abs +2.4 dB at ref 0, −1.6 dB after the trial; the 06-02 linear tap shows `linearMA ≈ cleanMA > nearMA`, placing the instability before the NLP) — and adaptation continuing through double talk is why the hotter reference made double talk catastrophically worse (near-speech similarity 0.080→0.0035, far residual +4.66→+21.50 dB). VERYAGGR's earlier "good" far-only numbers were the NLP crushing this diverging output along with the user's speech; AGGR merely exposed the truth, so iterating NLP levels and analog PGA cannot converge. Instead, rescale the reference **digitally** (exact, saturating, host-testable; both non-near PGAs back to 0) and let the already-written linear tap decide, in one flash and one fixture run, whether scale was the binding constraint or the engine must change (same-library VOIP mode with DTD/TDE, `afe_aec_create`, no model partition needed). Also fix the harness before the next verdict: the −40 dBFS far-only gates silently became 18.06 dB stricter when the worker ×8 landed (the trial runs' native far-tone, −40.9/−41.1 dBFS, would pass at ×1 framing), and 55–70 % of the PRBS/double-talk uplink samples rail-clip at ×8, destroying similarity diagnostics downstream of the device.

## 1. Actual ES7210 physical-input → TDM-slot order

**Wire order for this configuration (MIC1|MIC2|MIC3 selected, 4-slot 16-bit TDM I²S): slot 0 = MIC1 (near mic), slot 1 = MIC3 (electrical speaker divider), slot 2 = MIC2 (second acoustic mic), slot 3 = MIC4 (unselected, dead).** Proof classes:

- **Datasheet-proven (order mechanism):** the driver writes `ES7210_SDP_INTERFACE2_REG12 = 0x02` for ≥3 selected mics (`es7210.c:229-231`); the ES7210 datasheet (Rev 21.0, register map, `https://files.waveshare.com/wiki/common/ES7210_DS.pdf`; Rev 9.1 concurs) defines R12[1:0] `SDOUT_MODE` = 10 as "TDM I²S", and its **Figure 2e places Channel 1 and Channel 3 in the LRCK-low half, Channel 2 and Channel 4 in the high half** — pair-interleaved order MIC1, MIC3, MIC2, MIC4. The sequential order MIC1..MIC4 exists on this chip only in TDM DSP/PCM mode (R12=0x01, Fig 2g/2h), which this config does not use. The driver assigns nothing: selection is an order-free power bitmask, and deselected inputs keep their fixed slot (silent) rather than compacting. This matches the renegotiated wire geometry byte-for-byte (boot-log `ws_width: 32, total_slot: 4` = two 16-bit slots per WS phase).
- **Code-proven (register plumbing):** `esp_codec_dev_set_in_channel_gain` mask bit _i_ writes gain register `0x43+i` of MIC _i+1_, gated on that mic being selected (`_es7210_set_channel_gain`, vendored `es7210.c:347-364`; registers `es7210_reg.h:35-38`; 3 dB steps to 30 dB then 33/34.5/36/37.5, `get_db` `es7210.c:328-345` — 18 dB converts exactly to code 6, so no conversion bug exists; the framework truncates float→int first, `esp_codec_dev.c:440`). Masks address **physical mics, never slots**.
- **Measurement (on-board confirmation, new):** the mask-2-only 18 dB trial raised slot-1 level by a **uniform +7.3 dB across every playback phase** (05-41 vs 05-25; replicated in 05-52 within ±0.5 dB), and extending the same gain to mask 1 (MIC2) in the 06-02 partial run changed slot 1 by **≈0 dB** (steady far-phase `referenceMeanAbsolute` 1295/982/830 vs 05-41's 1294/1006/824). Slot 1 responds to REG45 and not to REG44. Codec inter-channel crosstalk (≈ −90 dB) cannot fake a uniform +7.3 dB, and slot 1 is flat during speech-only (prior-art interval peaks 4–12 counts; kit ambient refPeak 4–8), excluding acoustic bleed.
- **First-party cross-checks (all consistent):** Espressif's Korvo/Box BSPs run the same driver with all four mics, consume the stream through 32-bit stereo I²S (which pairwise-swaps 16-bit slots) with AFE `input_format "RMNM"` — undoing the swap yields wire [mic, **ref**, mic, unused] = MIC1, MIC3, MIC2, MIC4 — and their gain code sets `MAKE_CHANNEL_MASK(2)` to 0 dB with the comment `// reference` while boosting masks 0/1/3 (`esp32s3-korvo-1/bsp_board.c:109-118`); esp-webrtc-solution's default ES7210 pairing for mic+ref is `ES7210_SEL_MIC1 | ES7210_SEL_MIC3` (`components/codec_board/codec_init.c:510-517`); M5Unified configures CoreS3 with MIC1/MIC2 as the acoustic pair and never touches MIC3/4. Espressif's echo-reference convention on this codec is **physical MIC3**, and M5Stack's divider wiring matches it.
- **Prior-art telemetry is genuinely neutral on the MIC2-vs-MIC3 question** — reconciling the prompt's suspicion: `esp_codec_dev_open` calls `codec->enable(true)` (`esp_codec_dev.c:191-192`) → `es7210_start` → `es7210_mic_select`, which **rewrites every selected mic's PGA code to `codec->gain` = 0** (`es7210.c:197-224`; the 30 dB default written at `es7210.c:457` during the earlier `es7210_open` is immediately clobbered). Both acoustic candidates therefore sat at 0 dB in every prior-art run, so the −24…−39 dB slot-2 tracking ratio (which follows MIC1's PGA exactly) identifies slot 2 as _an_ acoustic mic at 0 dB without naming it. An independent audit of the prior-art tree read the same telemetry as "slot 1 = MIC2 at a surviving 30 dB open-default" — that reading requires the enable-time reset not to run, and the framework source shows it does run, so it is rejected.
- **What remains unproven:** the +7.3 dB-per-18 dB analog shortfall's physical cause. ADC rail-clipping is **excluded by the retained data** (post-trial far-phase `referencePeak` ≤ 3 387 ≪ 32 767, and the clip-insensitive mean-abs shows the same +7.3 dB); ALC is **excluded by datasheet + write inventory** (R16 `ALC SELECT` defaults off and is never written; R1B–R1E digital trims stay 0 dB). Leading hypothesis: PGA input-impedance loading of the divider network — switched-input PGAs drop input impedance as gain rises, and a realized/requested ratio of ×2.32/×7.94 = 0.29 fits a source impedance ≈ 2.4× the high-gain input impedance. §3's staircase settles it; §2 makes it moot for the signal path.

## 2. Is the both-masks reference PGA safe? Is there a cleaner method?

**Safe: yes — proven, not just argued.** Slot 2 never enters the AEC (`deinterleave_capture` consumes only slots 0/1, `core_s3_audio_owner.c:748-751`; slot 2 exists only in the boot-max `tdm_slot_peak` diagnostics), the 06-02 run shows the mask-1 extension has zero effect on slot 1, gains are applied once after `esp_codec_dev_open` and nothing re-enables the codec afterwards (`reset_aec` recreates only the ESP-SR handle; there is no codec reopen path), and `valid_options` bounds the value 0–37 dB. With identity now proven (§1), the both-masks hedge is also _obsolete_: mask 2 alone is the precise reference lever, and keeping mask 1 in the call merely raises the diagnostics-only slot 2. Two latent traps deserve a comment wherever the call lives: every codec enable rewrites all selected PGAs to 0 (`es7210_start`→`es7210_mic_select`), and `esp_codec_dev_open` itself ends by re-applying the whole-device `set_in_gain` value to every channel (`_update_codec_setting`, `esp_codec_dev.c:210`) — per-channel gains are persisted nowhere, so any future reopen path silently reverts them.

**But it is the wrong lever.** Three reasons: (a) it is _compressed_ — 18 dB requested delivered 7.3 dB, and if the loading hypothesis is right each further step delivers less, so the remaining 9–18 dB deficit is not reachable analog-side; (b) it is _entangled_ — it makes an analog unknown part of the production signal path when the measured quantity that matters is simply "slot-1 level vs slot-0 level"; (c) it is _slow to iterate_ — every trial costs a reflash, and this device currently requires a physical three-second bottom-RST ROM-loader entry per flash.

**Cleaner minimal method: pin both non-near PGAs at 0 dB and scale slot 1 digitally in `deinterleave_capture`** — a saturating ×8 (+18.06 dB) on the slot-1 sample before it becomes `reference_dma`. Exact in dB, host-unit-testable, zero analog unknowns, ~128 multiplies per 8 ms chunk (noise floor: idle reference is ~1 LSB mean-abs / 4–8 peak, so ×8 lifts it to ≈ −72 dBFS — irrelevant). Headroom is measured: the largest far-phase `referencePeak` at 0 dB PGA was 1549; ×8 → 12 392, no saturation, and the saturating clamp guards the pathological case. The reference SNR argument for analog gain does not apply here — the divider is an electrical signal ~50 dB above the ADC floor at 0 dB PGA; digital scaling preserves that ratio. (Espressif's "prefer analog gain" guidance in the `i2s_es7210_tdm` README addresses acoustic microphones, not electrical references.) A codec-side alternative exists — the ES7210 has per-ADC direct-dB digital trims R1B–R1E, −95.5…+32 dB in 0.5 dB steps, untouched by any enable cycle, with a **reversed register↔ADC mapping (R1C = ADC3)** — but the owner-side shift is preferred because it is host-testable and visible to the linear tap. The current uncommitted `mask(1)|mask(2) @ 18` code and its pinning test (`firmware-architecture.test.ts:928-969`) should be replaced by `@ 0` plus the digital shift.

## 3. The single discriminating measurement, and the numeric falsifier

**One flash, one run of the existing six-phase fixture against the deterministic provider, judged from `aec-metrics.json` steady far-PRBS windows.** The build: current working tree (linear tap, schema v3, AGGR) with §2's change — both non-near PGAs 0 dB, digital ×8 on slot 1. This simultaneously (a) endpoint-tests the reference-scale hypothesis at parity (predicted deficit after ×8: tone ≈ +4 dB, PRBS ≈ −1 dB, speech ≈ +8 dB — within the engine's documented "audio sent to the speaker" regime), (b) cross-checks identity/loading (expected far-tone `referenceMeanAbsolute` ≈ 8 × 552 ≈ 4 400 ± 20 %; ≈ 550 or ≈ 1 300 would mean the shift didn't land — at PGA 0 or with the analog 18 dB still in — and ≈ 10 300 would mean shift and analog 18 dB were stacked), and (c) uses the linear tap to attribute whatever remains.

**Falsifier, stated before the run:** if, with the reference within ±4 dB of the near echo, the **linear stage still fails to attenuate far-only PRBS by at least 12 dB** in steady windows (`linearMeanAbsolute / nearMeanAbsolute > 0.25`), or `linearPeak` still rails (≥ 30 000), then reference scale was **not** the binding constraint — stop tuning FD scale/NLP entirely and change the engine (§5 route C) or the reference source (§5 route B). Conversely, linear attenuation ≤ −12 dB with no rail peaks confirms scale was binding; proceed to double-talk calibration with the NLP at AGGR and judge the remaining gap against the (×8-normalized) −40 dBFS gate. The sub-proportional dose-response already observed (0.33–0.55 dB of far-only improvement per reference dB) is a genuine warning that this test may falsify the fix — that is what makes it discriminating rather than confirmatory.

If the staircase question (§1's loading mechanism) is still wanted afterwards for documentation, it is a five-minute experiment once a runtime gain knob exists (§6): step one mask at a time {0, 6, 12, 18, 24} dB during the far-tone phase and read `referenceMeanAbsolute` per step; identity falsifies if slot 1 ever tracks mask 1; loading is quantified by the realized-vs-requested slope (0.41 dB/dB measured at the 18 dB point).

## 4. Why the current linear+NLP path is unstable on broadband/double-talk — ranked

The measured signature: tone converges (−26…−30 dB), broadband _adds energy_ (PRBS +2.4 → −1.6 → +0.7 dB across the three AGGR runs; clean peaks 1.5–1.7× near peaks), double talk diverges harder the hotter the reference (+1.0 dB with 70 % worker-side clipping, near-similarity 0.0035), and the 06-02 linear tap shows `linearMA ≈ cleanMA` — the divergence is created by the adaptive filter, not the NLP.

1. **Reference scale (primary, dose-response-proven).** The engine's own contract describes `refdata` as the playback signal "sent to the speaker" (`esp_aec.h:91,107`) — i.e. a reference at or above echo level; it is being fed one 17–27 dB below. Every reference increase improved every far-only phase monotonically (tone −27.0→−30.1, PRBS +2.4→−1.6, speech −12.8→−15.2 per +7.3 dB). Whether the internal mechanism is fixed-point conditioning or step-size regularization tuned for playback-scale references is unknowable from outside the closed library; the dose-response and the linear-tap attribution are measurement. Caveat honestly: the response is sub-proportional, so §3 may yet falsify scale as _sufficient_.
2. **Adaptation control during double talk (no DTD in this engine — binary-proven).** The FD/SR AEC3 objects contain no double-talk detector and no time-delay estimator (the VOIP/DiOS objects contain both: `dios_ssp_aec_doubletalk_*`, `..._tde_delay_estimator*`, ERL estimation, residual suppression); the only adaptation control visible anywhere in the AEC3 family is a VAD on the _reference_ (`esp_aec3_*_write_ref_vad`, exercised in the shipped v1 AFE source). So during double talk the filter keeps adapting with near speech polluting its error signal — and a stronger reference drives larger, wronger updates, exactly matching the trial's double-talk collapse (near-sim 0.080 → 0.0035, far residual +4.66 → +21.50 dB). This is intrinsic to the FD engine; no NLP level fixes it.
3. **NLP policy (a masker, not a cause).** VERYAGGR's −41.6/−59.4 dBFS far-only numbers coexisted with double-talk near-similarity 0.138 — the NLP was suppressing the diverging linear output _and_ the user. AGGR (Espressif's default, correctly pinned at `core_s3_audio_owner.c:46` and by the uncommitted architecture test) merely stopped hiding the linear failure. Keep AGGR; `aec_set_nlp_level` is runtime-callable for experiments (`esp_aec.h:122-134`, FD-only per the library's own mode strings).
4. **Near-mic clipping during loud far playback (real secondary defect).** `nearPeak` hits 32 768 for 5–6 consecutive windows during far-speech-shaped in _every_ run — a clipped near signal is a nonlinearity no linear filter can cancel, and it coincides with the worst-behaved broadband phase. 24 dB near PGA + 100 % volume + this stimulus has no headroom; reduce the stimulus coefficient or accept the loss in that phase, but stop asking the AEC to explain it.
5. **Delay/phase (ruled out as primary).** The electrical reference is sample-synchronous by construction (one ADC frame), prior art cross-correlated the same path at **0.375 ms** lag, echo lag fits trivially inside one 32 ms partition of the 4 × 32 ms = 128 ms tail (filter_length units confirmed as 32 ms frames by disassembly: buffer span = `frame_size × filter_length`), and a gross misalignment would have failed the tone too.
6. **Filter length 4 (adequate).** Espressif's recommended value for S3; 128 ms covers the energetically dominant room response at this geometry; divergence (energy addition) is not a tail-length symptom.
7. **Polarity (irrelevant).** A linear filter absorbs sign; tone convergence proves the path is modelable.

## 6. Deletions and simplifications that shorten time-to-goal

1. **Delete analog reference calibration from the signal path** (§2): PGAs 0|0 + digital shift. This also deletes the physical-identity question from behavior — it becomes documentation.
2. **Make the far-only absolute gates uplink-gain-aware.** The −40 dBFS gates in `stackchan-aec-assessment` are evaluated on post-×8 audio since the 04:27Z policy change; the trial runs' native far-tone (−40.9/−41.1 dBFS) already passes the old framing. Either assess device-native (divide by the recorded `uplinkGainMultiplier`) or retain pre-gain PCM alongside. Without this, every future run fails regardless of AEC truth and the ledger keeps "regressions" that are policy artifacts.
3. **Stop letting ×8 destroy evidence.** 55–70 % of PRBS/double-talk uplink samples rail-clipped in the ×8 runs; similarity/residual numbers computed on clipped audio are unusable. Retain the native uplink (or both), and re-derive the smallest VAD-clearing gain after the AEC is healthy — the ×8 was calibrated against a broken AEC's output levels.
4. **Runtime knobs before the next tuning loop** (the largest single time-to-goal lever): `aec_set_nlp_level`, `esp_codec_dev_set_in_channel_gain`, and the digital shift factor are all safely callable at runtime; exposing them through the existing `kit.stackchan` capability route converts each future hypothesis from _physical ROM-loader entry + reflash + six-phase run_ into a remote call. The bottom-RST requirement has been the standing physical blocker for two days of log entries.
5. **Serialize the slot peaks with interval semantics.** `tdm_slot_peak[4]` is max-since-boot and absent from the AEC wire view (`metrics.c` field list) — the one telemetry that would have settled slot identity in a single run was invisible in every retained artifact. Exchange-to-zero on snapshot and add the four values to the view (schema already bumping to v3).
6. **Do not** touch: the slot constants (0/1 — correct), the AGGR pin and its test, the frame-exact transport, the 512-sample bridge contract (until route C), or the near-phase pilot design (the 431 Hz/−54 dBFS matched-path pilot is sound; the failing 0.85 near-repeat control is measuring real AEC misbehavior, and should recover with a healthy linear stage — treat it as a diagnostic, not a gate to relax).
7. **The local maximum, named:** the loop "adjust {NLP level, analog reference PGA} → physical ROM-loader entry → reflash → six-phase physical run → compare dBFS" cannot reach the goal from inside: two of its three knobs are now measured weak (NLP relocates the failure; analog PGA delivers 0.41 dB/dB and cannot close the deficit), each iteration costs physical presence, and the engine's missing DTD is invisible to it. The architecture around it (owner/bridge/lane seams, interval signal windows, the linear tap) is _not_ the local maximum — it is what makes the escape measurable.

## Recommended next sequence (≤ 5 actions)

1. **One flash** (single ROM-loader entry): current tree + §2's digital reference scale (PGAs 0|0, saturating ×8 on slot 1) + the §6.4 runtime knobs if they fit the day; keep AGGR, schema v3 linear tap.
2. **One six-phase fixture run** (deterministic provider, no Grok needed); judge device-native per §3: PRBS steady linear attenuation ≤ −12 dB and no linear rail peaks ⇒ scale was binding; otherwise scale is falsified — schedule route C (VOIP/DTD engine, 256-sample frames) as the next flash and stop tuning FD.
3. **Fix the harness accounting in parallel** (no device needed): gain-aware far-only gates, retain pre-gain uplink PCM, add interval slot peaks to the wire view.
4. **On a healthy linear stage, calibrate double talk**: rerun the fixture, expect near-similarity to recover materially (≥ 0.5 vs 0.0035); if far-only residual still misses the (now correctly normalized) gate, step NLP at runtime before touching anything else; if double talk still strips near speech at AGGR with a healthy linear stage, that is the FD engine's missing DTD — go to route C.
5. **Only then return to the provider edge**: re-derive the smallest uplink gain that clears Grok's server VAD against the healed clean signal (the ×8 figure predates a working AEC), then run the deferred interruption/turn proofs.

## Uncertainties

1. M5Stack has never published the CoreS3 divider wiring; "MIC3 = divider" now rests on the datasheet slot order + measured slot-1 behavior + Espressif's MIC3-reference convention, which is as close to proof as exists without the schematic.
2. The analog +7.3-of-18 dB shortfall's mechanism (impedance loading vs something else) is untested — ADC clipping and ALC are excluded (§1); it becomes irrelevant under §2 but the §3 staircase can settle it cheaply once knobs exist.
3. FD_HIGH_PERF's internal arithmetic (fp32 vs int16 FFT family) is inferred from symbol names; the scale-sensitivity conclusion rests on the measured dose-response, not on that attribution.
4. VOIP-mode suppression depth and CPU on this hardware are unmeasured; route C's promise is architectural (DTD/TDE present), not yet acoustic.
5. Per-run firmware build hashes are not recorded in evidence; run identity was pinned by commit timing, wire schema, and reference-level telemetry. Adding a build hash to `capability-description.json` would close this.
6. The 06-02 partial run aborted network-invalid at near-repeat; its steady far-phase reference levels are used only for the mask-1 null result, which needs no phase completion.
