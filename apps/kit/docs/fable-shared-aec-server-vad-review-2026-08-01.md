Reviewed read-only at `c-capabilities`, HEAD `e349e442e` plus the **uncommitted** `apps/kit/src/userspace/config-worker/*` working-tree changes (which contain most of the reviewed userspace design; `1d96809c9` — the PSRAM delta — and `e349e442e` landed *during* this review). Method: first-hand reads of the control-plane contract (reconciler, transport handshake, worker `/pcm`, conversation capability, target wiring) plus five delegated deep audits: CoreS3 platform vs ESP-IDF 5.4.2/esp-sr 2.4.7/esp_codec_dev vendor source, userspace bridge, portable PCM data plane + tests, the prior-art StackChan checkout (read-only, untouched), and HAVPE/ESPHome first-party source (local checkouts) with docs.x.ai primary-source grammar research. Every load-bearing subagent claim cited below was spot-verified in source by me. Nothing was modified, committed, or flashed; one memory note was written outside the repo.

## 0. Verdict

**The proposed design is already implemented, and it is the right one — do not redesign it.** The authenticated `X-Iterate-Kit-Audio-Mode` handshake header exists on both ends (`platforms/iterate_esp_idf/pcm_transport.c:296-335`; `config-worker/routes.ts:118-121`, closed union, 400 on unknown), userspace derives `server-vad` vs `manual` from it in exactly two places (`worker.ts:314,428`) with no device-name branch anywhere, and the shared reconciler is mode-aware with a host test for the full-duplex policy (`components/core/src/audio_intent_reconciler.c:44-85`; `tests/audio_intent_reconciler_test.c:170-205`). StackChan declares `FULL_DUPLEX_AEC` at all three wiring points (`targets/stackchan/main/main.c:577,614,774`). The Grok grammar is code-clean for server VAD and matches both docs.x.ai and the only physical prior art. The PSRAM envelope move is sound. What stands between here and a trustworthy physical proof is four cheap BLOCK items (§6) — one firmware fatal-latch race, one barge-in session-death posture, one gain/tuning remediation package, one metrics-export gap — plus the failing tests in §7.

## 1. The contract (Q1): smallest clean design, confirmed; three hardening gaps

A KV/project-config alternative to the header would be strictly worse: whether zero-length markers exist on the wire is **compiled into the firmware**, so policy must travel with the socket that speaks it; a project flag could disagree with the running binary and the worker's marker-`#fail` (`pcm-proxy.ts:580-587`) would then kill every session. The header is per-device (Stick PTT + StackChan AEC coexist in one project), authenticated before it is read (`worker.ts:218-234` — auth precedes mode/identity parsing, and all validation precedes the `4001` replacement of the old session at `:243`, so a bad connect cannot kill a healthy one), immutable per PCM generation, and re-derived for provider reconnects from the same session field. Mode split-brain is structurally detectable: full-duplex firmware *cannot* emit a marker (`pcm_capture_turn` runs in `SUPPRESS_END_MARKER`; test `pcm_capture_turn_test.c:389`), so a marker arriving in a server-vad session proves a mis-flashed device.

Ordering/lifetime audit found no bug in the contract itself: replacement closes old-before-accept (`worker.ts:243`), device-event subscription retries a 0–8 s ladder for the cold-boot `/pcm`-before-mount race (`:529-573`), the project capability session lives exactly as long as the device socket (`:361-372,381-397`), and PTT edges are double-rejected in full-duplex (firmware `audio_intent_reconciler.c:57-61`; server `device-events.ts:210-232`, diagnostic not close).

Three hardening gaps, all small:
1. **Zero-init trap**: `ITERATE_KIT_AUDIO_PUSH_TO_TALK = 0` (`core/include/iterate/kit/audio.h:17`), so a target that memsets transport options and forgets `audio_mode` silently declares PTT — the exact reconciler/header disagreement the design exists to prevent. The Stick sets it explicitly (`targets/m5sticks3/main/main.cpp:1245`); the next port might not. Make 0 the invalid value so `prepare()` rejects it.
2. **Triple declaration**: StackChan states the mode separately for reconciler, transport, and audio owner. One `#define STACKCHAN_AUDIO_MODE` in `stackchan_realtime_policy.h` used three times makes drift impossible.
3. Duplicate `audioMode → turnDetection` ternaries at `worker.ts:314` and `:428` — compute once on the session.

## 2. Grok server-VAD grammar (Q2): conformant; the risk is acoustic, not syntactic

**Docs-verified grammar** (docs.x.ai speech-to-speech guide, realtime reference, and the published `voice-realtime.ws.json`): `turn_detection.type` is `"server_vad"` or `null` only (no `semantic_vad`); `input_audio_buffer.commit` is "only available when turn_detection type is null"; under VAD the response is auto-created after `speech_stopped` and **interruption is automatic** ("use response.cancel for manual cancel in non-VAD mode"); playback flush is client-owned — xAI's own cookbook clients stop playback on `speech_started` and send neither `truncate` nor `cancel`; `response.create` is legal in VAD and is xAI's own pattern for text-seeded greetings and post-`function_call_output` continuation; 120-minute session cap; documented session resumption via `?conversation_id=` + `resumption.enabled`. The prior-art checkout physically ran exactly this on this hardware: bare `{"type":"server_vad"}`, continuous binary PCM, zero commits, zero clears, zero `response.cancel` in any evidence journal.

**Kit conformance is clean and test-pinned.** In VAD mode no path can emit `commit` or `response.create`-after-commit (`pcm-proxy.ts:601,915-920` unreachable; test `pcm-proxy.test.ts:309-377` asserts both counters zero); a device marker fails the session loudly (`:580-587`); the greeting and tool-continuation `response.create` (`:1407-1441,1157-1165`) match the documented xAI pattern; empty manual turns are absorbed, VAD has no turn to be empty. Two grammar-adjacent tunables are wrong by evidence, though: the kit sends the **bare** `turn_detection` shape (default threshold 0.85, undocumented silence default), and prior art's final live run at exactly that shape shows heavy turn fragmentation — three `speech_started` micro-turns in 1.1 s, each spawning its own response. Prior art's current source adds `silence_duration_ms:1000, prefix_padding_ms:400` (never physically run, but docs-legal). Send explicit params.

**Speech-start interruption**: the design is a worker-side pacing-ring discard plus an out-of-band Cap'n Web `interruptPlayback` used as a playout fence — the scheduler withholds new-response audio until the device acknowledges the physical purge (`pcm-proxy.ts:721-765`; device single-admission async fence with 50 ms ack budget, `capabilities/src/conversation.c:87-139,181-245`, where timeout fails only the promise, never the purge). Stale binary during speech is dropped (`:841-844`); a VAD-cancelled `response.done` keeps the fence (`:939-956`). This is correct in shape but has one session-fatal posture and two bounded races — see B2 and DEFER items. The residual stale tail if the fence degrades is bounded by the 8-frame/160 ms lead plus the device's 400 ms age gate — the accumulating-delay invariant holds regardless.

**Why grammar isn't the battle**: prior art's failures were never wire-shape failures. They were acoustic — raw mic pinned at full scale during playback, clipped (nonlinear) echo surviving AEC, self-transcription ("Yes, I can hear you.") and double answers, with a measured gain cliff: 37 dB analog → 5.4 % clipping and semantic echo leak; 18 dB → VAD completely deaf for 52 s; the proven point is **24 dB analog + 12 dB digital uplink**. The kit runs 24 dB with no digital stage and no runtime knob (B3).

## 3. Physical pipeline + PSRAM delta (Q3)

The CoreS3 platform audit found the fast-port review's F-ledger substantially landed: AW88298 reg 0x06 RMW-verify after both codec opens (`core_s3_audio_owner.c:40-42,254-280,396-400`), ES7210 per-channel gains with reference at 0 dB, 5×128 DMA (8 ms granule, `auto_clear`), IRAM tap → 8-slot poison-epoch reserve → core-1 AEC task, esp-sr `FD_HIGH_PERF`/filter 4/NLP 2 with **queried** chunk size and PSRAM state via `.caps` (`:414-438`) — the proven prior-art configuration, not the notes' unproven `FD_LOW_COST`. Task map is sound: IO prio 23/core 1, AEC 20/core 1, PCM net 6/core 0, control 5/core 0; LWIP (18, no affinity) sits below both audio tasks. Reframing 512↔320 is fixed-storage with ~52 ms structural worst-case partials, no history queue. Freshness is destructive at every layer (reserve poison, 640 ms uplink ring tied to the sender policy by static assert `main.c:109-111`, 400 ms downlink age, generation fence before new-socket admission at `pcm_transport.c:194-228`) — **no mic backlog, no stale-replay path, no unbounded queue was found**. The uplink gate is properly wired: reconciler → `request_uplink_active` → `pcm_capture_turn_request` (`owner.c:1129-1142`), one control producer, so full-duplex needs zero new plumbing.

Two real defects and one exposure:

- **The bus format is owned by `esp_codec_dev`'s open-time renegotiation, not by the owner's I2S configs.** `audio_codec_data_i2s.c:236-282,409-520` rewrites TX slots when the 4-channel mic opens; the 64-BCLK outcome, the slot-1=MIC3 reference map, and the 256 B/8 ms accounting are all *measurement-anchored*, not code-guaranteed, and will break silently on a component bump. Cheap fix: read back and assert final geometry at owner start (F4).
- **`restart_for_freshness` fatal-latches on an empty ring**: it has no `UNAVAILABLE` branch (`pcm_uplink_sender.c:242-246`) although the normal acquire path treats `UNAVAILABLE` as IDLE (`:329`); a producer's epoch-flag store landing just after a drain empties the ring turns a recoverable stall into `SENDER_FAILED` → `CONDUCTOR_FAILED` (`pcm_uplink_conductor.c:432-437`) → fatal latch (`pcm_transport.c:571-573`) → reboot mid-call (per `8389051e4`). Verified end-to-end first-hand. This is B1.
- **Volume 100 % + the +15 dB map with no limiter** (`owner.c:46-55`, `main.c:778`) is the goal's "high-volume" setting and simultaneously the mechanism prior art proved causes reference/mic clipping and self-answers; the sibling amp measurably distorts at full scale (`1d96809c9`). `tdm_slot_peak[1]` would falsify reference clipping but is not exported (B4).

**PSRAM delta: sound as landed.** The move is exactly the two 8×8 KiB control envelope arrays (`main.c:119-138`), touched only by the prio-5 control network task and the prio-1 main loop — no ISR, no DMA, no flash-cache-disabled window; WS/TLS staging stays internal; ring indices/lengths stay internal, so atomics never target PSRAM (the S3 erratum workaround is enabled anyway, sdkconfig:1994). `SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY=y`, quad/80 MHz, Wi-Fi/LWIP allocations kept internal. Linker BSS over `heap_caps_malloc` is the right call for the stated reason (deterministic link-time failure). No smaller safe design is warranted — 8 KiB is the wire envelope cap, and the binary/partition claim checks out (1,138,912 B on disk ≈ 22 % of the 5 MiB app slot). The one real cost: `SPIRAM_FETCH_INSTRUCTIONS`+`RODATA` means code fetches now share quad-PSRAM bandwidth with AEC state and these rings; `maximum_aec_linear_us` is the canary and is currently unexported — folded into B4.

## 4. HAVPE boundary (Q4)

First-party source settles it: on HAVPE the **XMOS XU316 does all DSP in hardware** (AEC → interference canceller → NS → AGC, 16 kHz, `voice-kit-xmos-firmware` ffva-int fixed-delay build), the ESP32-S3 is an **I2S slave on both buses**, and processed mic arrives as 16 kHz/32-bit stereo where ch0 is the full-pipeline tap (`home-assistant-voice.yaml:1495-1512`) — i.e. the kit's PCM-v1 capture format, natively echo-cancelled, no esp-sr anywhere. Playback is 48 kHz/32-bit/stereo on an XMOS-mastered bus with the DAC's DIN electrically tapped as the echo reference; the AIC3204 register recipe is copyable from `esphome/components/aic3204/aic3204.cpp`; the XU316 boots from its own flash (release reset GPIO4; I2C DFU only for updates; blob publicly released and md5-pinned). Native ESP-IDF port is feasible and preferable to riding ESPHome.

Consequences for the current change: **the seams already chosen survive unchanged** — an audio owner that produces echo-cancelled 16 kHz frames and consumes playback frames, plus the mode header ('full-duplex-aec' on HAVPE means "trust the wire's cancelled mic"). The HAVPE owner adds one seam the CoreS3 work must not preclude: playback-rate adaptation (16 k→48 k, 3:1) *inside* the owner. Nothing in shared code currently bakes in CoreS3 assumptions — TDM slots, esp-sr calls, 8 ms chunking, AW88298, and ESP-as-I2S-master all live in `platforms/iterate_core_s3_audio` and the patched BSP, which is the correct side of the boundary. Reusable from first-party HAVPE: the codec recipe, the boot/reset sequence, the tap-select I2C protocol. Not reusable: ESPHome's component runtime, its speaker/mixer graph, and any software AEC (there is none to reuse — verified by grep).

## 5. Deletions and simplifications (Q5)

- `components/core/voicelab_stream.c` (1,281 lines + header) is referenced only by the Waveshare probe target — gate it out of device builds or delete when that rig retires.
- `pcm_playback_interruption` embeds a second private fence; it is expressible as a token client of the one generation fence (−134 lines core, one fewer fence service per 8 ms pass). Post-proof cleanup.
- The PTT marker machinery (reserved lane slot, EMIT branch, marker-preserving drains) is dead-in-mode for StackChan but shared with live PTT targets — keep, do not fork.
- The deterministic tone provider speaks only the manual grammar (`providers.ts:264-291`): in `tone`+`full-duplex-aec` no response can ever be triggered. Add a small server-vad variant (emit `speech_started/stopped`, auto-respond) rather than a new harness — it is also what makes the portability-notes deterministic full-duplex rung runnable through the *deployed* worker.
- The local bridge's server-vad `#suppressDownlink` latch (fast-port A-2) is **still unfixed**: `requestTextResponse` sets it with no mode guard (`src/voice/device-pcm-proxy.ts:518-531`) and the only clear is PTT-scoped (`:671-677`), black-holing all audio (`:711`). Fix it or drop text-turn local rungs.
- Do not add an in-band PCM flush message: the out-of-band fence plus 160 ms lead plus 400 ms age gate already bound staleness; protocol v1 purity is worth more than shaving the degraded-mode tail.

## 6. Ranked findings (Q7)

### BLOCK before flash

**B1 — empty-ring epoch-take fatal latch** (`pcm_uplink_sender.c:242-246`). A mid-call stall can end in a reboot instead of a socket restart, poisoning unattended physical evidence with mystery resets. *Shortest correction*: in `restart_for_freshness`, treat `acquire_if_needed == UNAVAILABLE` as "nothing to purge" — count the restart with 0 discards and return RESTART (~4 lines). *Acceptance*: new host test `epoch_reset_flag_with_empty_ring_is_not_fatal` red→green; a stall-injected run shows `uplink_restart_incidents` advancing with `fatal_failure_latched` remaining 0. This preserves the real-time invariant the latch was protecting (no stale epoch escapes) without converting recoverable pressure into device death.

**B2 — barge-in can kill the session, and barge-in bursts are the expected case.** `#handleServerVadSpeechStarted` fires the Cap'n Web fence on *every* speech start (no `#responseActive` guard, `pcm-proxy.ts:721-752`); any fence rejection — device "already pending" (single admission, `conversation.c:109-114`), unavailable project session (`worker.ts:287-289` throws), or ack failure — routes to `#fail(4000)` (`:767-783`), closing the device lane. Prior art measured three `speech_started` in 1.1 s under this exact VAD config. *Shortest correction*: worker downgrades interruption failure to degraded-flush (clear fence, count, continue — staleness stays bounded by the 400 ms device gate); device makes `interruptPlayback` idempotent-success when no playback is queued or a purge is already in flight; skip the fence entirely when no response is active. *Acceptance*: failing tests 2–3 in §7 red→green; a physical barge-in run ends with `playbackInterruptionFailures ≥ 0` and close code ≠ 4000. This keeps audio ownership independent of control-lane liveness — the invariant the prompt names — instead of coupling call survival to a Cap'n Web round trip.

**B3 — make the likeliest first-run failure remotely tunable before flashing.** Uplink sits ~12 dB below the only proven-working level (24 dB analog, no digital stage, vs prior art's 24+12; 18 dB was VAD-deaf, 37 dB self-answered); `turn_detection` is bare (fragmentation-proven); gains/volume are boot-only options (`core_s3_audio_owner.h:38-39`) with no limiter at 100 %. *Shortest correction*: (a) a digital uplink gain applied to AEC-clean frames in `copy_clean_uplink`, default +12 dB; (b) port the Waveshare's `setVolume`/`setMicGain` live capability calls (`1d96809c9` pattern) to StackChan; (c) send `silence_duration_ms` + `prefix_padding_ms` explicitly in `providers.ts`. *Acceptance*: first VAD run shows `speech_started`/transcription events in the provider stream; gain iteration happens over Cap'n Web, not reflash; no self-answer in a single-turn far-end test. Without this, the operator-away requirement collides with a boot-constant on the most evidence-laden failure axis.

**B4 — export the AEC falsifiers.** The owner computes `tdm_slot_peak[4]`, AEC linear/NLP µs max, recreates, reserve overflows, receive-to-render — and `sample_runtime_metrics` forwards none of them (`main.c:273-343`; schema has no AEC fields). The goal's "streamed metrics … metrics sufficient to falsify AEC quality" is currently unsatisfiable remotely, and a dead reference slot (prior art captured an all-channels-silent wedge) would be invisible. *Shortest correction*: add five fields to the audio metrics schema — near/ref slot peaks, `max_aec_linear_us` + `aec_recreates`, `underrun_incidents` + `receive_to_render_ms`, reserve overflows, and a near-vs-clean energy ratio (ERLE proxy, one subtraction) — plumbing only. *Acceptance*: a far-end-only run adjudicated entirely from the live metrics subscription plus the Mac oracle.

### FIX before HAVPE

- **F1 — provider liveness under VAD**: a failed `#ensureProvider` never retries (`worker.ts:466-527`) and VAD has no commit path to nudge it (manual mode does), so one failed reconnect silently kills the call; mic frames drop silently meanwhile (`pcm-proxy.ts:610-621`); `#serverVadSpeechActive` is not reset on detach (first post-reconnect `speech_started` becomes a no-op interruption); provider recycling discards conversation context — xAI's documented resumption (`?conversation_id=`) is the remedy. Bounded retry ladder + state reset + (optionally) resumption.
- **F2 — H2 stands**: provider death mid-response never sends the device end-marker (`#detachProvider` `:1510-1528` makes `#finishDownlinkResponse` unreachable), leaving firmware `response_active` stuck through underrun silence. Send the marker on detach-with-active-response.
- **F3 — no escalation from repeated in-place freshness recoveries** (conductor): a connected-but-zero-throughput socket purges mic audio every ~500 ms for minutes until TCP RTO. Escalate to socket replacement after N consecutive in-place recoveries without a SENT.
- **F4 — assert final bus geometry at owner start** (read back channel info + pin the codec-dev format log) so component bumps fail loudly, per §3.
- **F5 — rationalize worker session-death postures**: distinct close codes for backpressure vs marker-mismatch vs overflow (all 4000 today), and consider detach-reconnect instead of session death for provider-side backpressure (checked per mic frame at 50 fps and on every keepalive pong; captun fakes have no `bufferedAmount`, so these branches are untested and live only under workerd).
- **F6/F7** — local-bridge latch fix and the server-vad deterministic provider (§5). **F8** — enum zero-trap + single mode constant (§1). **F9** — the TS↔C startup-lead/age guard (grep-the-header pattern already exists in `firmware-architecture.test.ts`; nothing ties `DEVICE_INITIAL_LEAD_FRAMES=8` to the 400 ms policy today).

### DEFER

Late-tail splice window between `speech_stopped` and the next response's first binary (`pcm-proxy.ts:813-827` — bounded, counter-visible); in-flight-PCM vs out-of-band-reset race (bounded by the 16-frame socket gate + 400 ms age filter); mid-call uplink purge invisible to server VAD (counters only — same class as reconnect mic loss); unused `conversation.item.truncate` (playback-position fidelity) and the undocumented `keep_context` field; codec-write 1 s hidden timeout ×3 before fail-closed; I2S ISR on core 0 and LWIP affinity (bounded by priority, watch counters); one-attempt PCM start per conversation (`main.c:686-699` — remote conversation restart suffices for run 1); discarded `inputStarted/inputStopped` returns (manual-only now); torn generation/connected read and unbounded-by-construction drain loops (self-correcting/practically bounded); voicelab/interruption-fence deletions (§5).
