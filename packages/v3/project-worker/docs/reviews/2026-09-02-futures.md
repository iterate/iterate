# Futures trawl — what the clean room will NEED, and what will be AWKWARD

> A read-only survey, 2026-09-02, of `apps/os` (the shipped product), the design corpus
> (`apps/os/docs/**`), the branch's own record (`BUILD-LOG.md`, `SIMPLIFICATION-LOG.md`,
> `docs/plan-one-fetch-rules.md`, `docs/proposals/*`), `tasks/**`, and the sibling v3 packages —
> checked against the clean-room surface as built (`docs/itx-surface-as-built.md`, `LAYERS.md`).
> Nothing here is a proposal to build. It is a ledger of what exists or is planned elsewhere and
> where it lands on today's doors.

## Summary (five lines)

1. **The doors are right.** Roughly three quarters of what apps/os does falls out of today's six doors
   (a rewrite rule, a subscription, a hosted facet, a stateless worker, a plain event, a built-in root)
   with no new abstraction — including the whole agent stack, integrations, live state, and the repo/worker split.
2. **Two gaps are structural, not incremental**: there is no way to say _"wake me later"_ (facets have no
   alarms — workerd#6810 — and the clean room deleted the parent alarm-proxy), and there is no way to say
   _"who is calling"_ (`authenticate()` is a no-op and no call carries an actor).
3. **Three gaps are big-but-door-shaped**: ingress by hostname + apps + the fetch-rules middleware (the
   parked `plan-one-fetch-rules.md`), the build tier (repo → bundler sidecar → artifact cache → budget),
   and secrets (the write door and the origin pin were deleted; the placeholder grammar has already diverged).
4. **One gap is invisible until it bites**: apps/os measured a _silent_ delivery stop at the 10,000-subrequest
   budget and permanent event skips from `Subrequest depth limit exceeded`. The clean room's delivery is
   faster but structurally similar and has never been measured at that duration.
5. **The owner's record is unusually explicit about what NOT to copy** — 25 rulings collected in §4,
   from the `rpc-targets.ts` god-object to dead-letter queues, JSONata transforms, five receiver kinds,
   server-held per-tab cursors, remote processors and the whole malicious-client defence family.

**One caveat on sources.** `apps/os/docs/itx-design.md`, `itx-later.md` and `itx-authority-research.md`
each carry an explicit banner: they are _historical design records_ written against the pre-itx-v4 layer,
**whose implementation was deleted in PR #1585**. Their horizon ideas (self-description as load-bearing,
one source address, the ingress restorer, the two-tier access model) still inform the shipped engine, but
"SHIPPED" inside them means "shipped in code that no longer exists". Current-state anchors in that corpus
are `architecture-review-2026-07.md`, `operator-sessions.md`, ADR 0002's amendment, ADR 0005,
`removed-test-coverage-itx-v4.md`, and the itx-later note on bundling (#1612 / #2144).

## 1. How to read the verdicts

The clean room's doors, in the order `LAYERS.md` builds them:

| Door                 | What it is                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| **built-in root**    | a key in `context/built-ins.ts` — the physical layer (`kv`, `fetch`, `facets`, `workers`, `rpcStubs`, …) |
| **rewrite rule**     | `provide(match, target)` → `itx/rewrite-rule-configured { match, target \| null }`                       |
| **rpc stub**         | a client's live value lent under an opaque key, borrowed by the DO, paged back                           |
| **subscription**     | `subscription-configured { name, target, consumes? }` + the one delivery loop                            |
| **hosted facet**     | `itx.facets.get(name, { source, cacheKey?, className })` — a durable loaded class                        |
| **stateless worker** | `itx.workers.get({ source, cacheKey?, className?, props? })`                                             |
| **plain event**      | anything spelled as `itx.append(...)`; the durable spelling of every verb                                |
| **edge verb**        | `cd` / `invoke` / `provide` / `subscribe` / `enableProcessor` / `disableProcessor`                       |

- **FITS** — falls out of a door as it stands.
- **STRETCH** — needs a small addition to an existing door (named in the note): a field on an event,
  an argument on a built-in, one extra built-in root.
- **AWKWARD** — needs a new door, a new event family, a new layer, or contradicts a landed doctrine.

## 3. The AWKWARD ones, ranked by how much they force a redesign if discovered late

### 3.1 — Authority: nothing carries an actor ⚠️ rank 1

**What apps/os has.** Eight credential lanes resolving to `{actor, grants[]}`; `assertCanAccessProject`
in every RpcTarget constructor; a private `streamDeliveryAuthContext` brand that no public lane can
forge; admin-only verbs; a `project-app-session` HS256 token verified locally at the door; and
`ProjectAuth` — a partial `fetch` that owns login/callback/logout for a project's own web apps.

**What the clean room has.** `authenticate()` returns the session unchanged, deliberately
(BUILD-LOG inc. 33, owner: "implement `.authenticate()` now but it should not actually do anything").
`projects.get(id)` reaches any project. No call carries a principal, and no event records one.

**Why it ranks first.** Everything downstream would have to learn about identity: the edge, the
session catalog, `cd`, the fetch lane, the event envelope. Retrofitting `metadata.actor` into an
existing log is worse than adding it now — history has no actor and never will.

**The smallest change that makes it FIT.** Three bounded pieces, none of them a new layer:

1. `authenticate(credentials)` resolves through `FALLBACK.invokeCapability('itx.auth.…')` — the shell
   contract already exists — into `{ actor, grants }` held on the `Session`;
2. `ProjectCollection.get(projectId)` refuses a project no grant covers (the enforcement point apps/os
   describes as "the auth worker RESOLVES, itx ENFORCES");
3. the edge stamps `metadata.actor` on every event it appends.

Per-call authorization _inside_ a project is explicitly **not** wanted — "everything in a project is
trusted to do everything in a project" (`processors-jam.md:227-234`), attenuation is per-context.
So the surface stays default-deny-by-rewrite-rule and nothing on the dispatch path changes.

**The residue that is genuinely a new layer.** `ProjectAuth` (a browser session for a project's own
app) and operator grants need a token mint and a cookie, and they live at the edge of the DO's world.
apps/os's operator sessions are worth reading before designing anything here
(`apps/os/docs/operator-sessions.md`): an HMAC-SHA256 grant delivered **after the URL fragment** so it
never reaches the edge or a `Referer`, redeemed into an HttpOnly host-only `SameSite=Strict` cookie,
15 minutes by default, **origin-bound, and deliberately unrevokable before expiry** ("stateless bearer
capabilities"), with a _synthetic_ organization id so stale-claim fallbacks cannot authorize a sibling
project. The parked fetch plan names the built-in `itx.auth` (C14) and gives it a control-plane hop —
the right shape, not yet designed.

---

### 3.2 — Time: nothing can say "wake me later" ⚠️ rank 2

**The platform fact.** workerd facets cannot set alarms — `ActorSqlite::Hooks::scheduleRun()` throws,
`AlarmScheduler` keys by `{uniqueKey, actorId}` with no facet dimension, workerd#6810 open
(`tasks/facet-alarms-for-userspace-processors.md`; `subscriptions-facet-spike.md:29-31`). apps/os
answers this with a **parent-owned alarm proxy**: `Stream.proxySetAlarm/proxyDeleteAlarm/proxyGetAlarm`
(min-merged shared slot) and `DynamicWorkerCapability.setAlarm/getAlarm`. The clean room **deleted**
that proxy along with the subscription-forwarder facet (BUILD-LOG, onion step 2+3), and the SDK host
says so out loud: _"NEVER define `alarm()`: facets have none … a timer, when one is needed, will be a
scheduled append on the context, not an alarm here"_ (`src/sdk/stream-processor-durable-object.ts:26-28`).

**What that costs.** Not one feature — a class of them. The scheduler (cron/interval/one-shot with
executions and an orphan sweep), LLM request deadlines (apps/os measured two turns sitting past their
deadline for **four days** across 245 prd agent streams), debounce timers, retry sweeps, heartbeats,
approval expiry, sandbox idle-sleep. A processor that only reacts to events cannot act on the absence
of events. `tasks/streams-core-clock-durable-timers.md` says it plainly: _"Nothing in the system can
wake a dead host when no events arrive."_

**The smallest change that makes it FIT** — and it is small, because the DO already owns an alarm:

- one built-in root `itx.alarms` with `set(name, atMs)` / `delete(name)` / `list()`, reduced into core
  state as one more slice beside `subscriptions` (a fourth control-event family: `alarm-set { name, atMs | null }`);
- the DO's existing `alarm()` handler min-merges the desired times with the quiesce and cursor-retry
  obligations it already re-derives, and on firing **appends an ordinary event** `alarm/fired { name }`;
- a processor that wants a timer subscribes to `alarm/fired` like any other event.

That is ~60 lines, adds no new door (a built-in root plus one event family — the shape the record already
sanctions for subscriptions), keeps "control is ordinary events", and makes the scheduler an ordinary
userspace processor. It also deletes itself the day workerd#6810 lands, exactly as the spike predicted.

### 3.3 — Ingress: hostnames, apps, and the fetch-rules middleware ⚠️ rank 3

**What is missing.** The only way into a context today is `/api` (capnweb) and
`/expression?context=&itx=`. There is no host→project resolution, no `itx.apps.<label>` convention,
no static-asset story, and no rules walk in front of the egress tail.

**Why it ranks here rather than first.** The design is _already written_:
`docs/plan-one-fetch-rules.md` specifies it end to end (C8 ingress by hostname label, C10 `itx.fetch`
as the one built-in with the walk in front of the tail, C11 rules as middleware with the
`x-itx-fetch-below` resume stamp, C12 `cd(...).fetch` as a native DO→DO hop). The 101-through-the-graph
half — the part apps/os _cannot_ do — is already built and proven here.

**The one open decision (D3).** Where a rule's matcher lives. The onion closed the door on
"a mount carries a policy", so the plan's own recommendation is right: **a `fetch-rule-configured
{ name, target, match? }` event family reduced as one more core-state slice**, exactly like
`subscription-configured`. Two commands, ~60 lines, and mounts stay `{match, target}`.

**The residue that is genuinely awkward.** Static assets. apps/os keeps them out of Worker Loader
entirely and re-enters the bundler sidecar for each asset lookup — and says of its own design that it
is _"faithful and simple for small apps, but not a large-asset architecture"_
(`dynamic-worker-build-requirements.md:156-163`). A clean-room loaded worker can serve only what its
modules contain. There is no design anywhere in either corpus for host-owned assets in R2/KV. Treat
this as unsolved rather than deferred.

**Also inherited:** every known-host request wakes the ROOT DO — and since the clean room's constructor
appends `created`/`woken`, a scanner hitting unknown-but-well-formed hosts would _materialize_ contexts.
The control plane must check slug existence before dialling (the plan's C15 says so).

### 3.4 — Build: repo → bundler → artifact → budget ⚠️ rank 4

**What apps/os has, in one line each.** A stateless workerd **sidecar** running
`@cloudflare/worker-bundler` (the OS worker never imports the 13 MiB esbuild wasm); a
**content-addressed build key** = sha256 over the resolved source identity (repo head content hash,
not the commit oid, so equivalent commits share one artifact _across projects_), the build options,
the bundler version and the artifact schema version; a **KV artifact cache** (one JSON record per key,
30-day TTL, bounded by KV's 25 MiB value limit); a **single-flight coordinator DO** per build key that
also retains the artifact in memory to bridge KV's negative-cache window; and **budgets**
(15 000 ms for a project host, 1 500 ms for a browser document navigation, **0** for stream delivery),
past which the caller gets `WorkerBuildInProgressError` by _name_ (class identity does not survive RPC)
or a 503 `x-iterate-worker-building` page that polls itself.

**What the clean room has.** Exactly the right primitive and nothing above it:
`workers.get({ source, cacheKey })` / `facets.get(name, { source, cacheKey })`, where a producer
expression runs inside Cloudflare's own `LOADER.get(id, getCode)` and is refused without a key. The
owner checked apps/os before landing it and ruled the tier above _"belongs to a build capability, not
to the loader door"_ (BUILD-LOG, decision F).

**The smallest change that makes it FIT.** Nothing new at the loader door:

- `itx.build` as an ordinary **hosted facet** — the single-flight coordinator, keyed by build key,
  with the artifact in KV (or R2 when it outgrows a KV value);
- the bundler is a **second deployed worker** (a sidecar), not a loaded isolate — the 13 MiB wasm and
  the 128 MiB isolate ceiling make that a topology fact, not a preference;
- `source: "itx.build.artifact('<buildKey>')"` with `cacheKey: '<buildKey>'` — the producer path as designed;
- **one new field**: `budgetMs?` on the worker/facet spec, and one new code `BUILD_IN_PROGRESS`, which
  the fetch lane renders as the 503.

**Honest residue.** A repo capability must exist first (§2.11), and the npm-install semantics
(no lockfiles, no lifecycle scripts, text files only, ranges re-resolve) are inherited constraints —
including the hermeticity bug the record flags twice: _"npm ranges re-resolve at build time, so the
'immutable' build key isn't. Pin resolved deps into the key"_ (`open-questions-and-interview.md:30-33`),
and more bluntly: _"Current artifacts expire after 30 days. Worse, the code explicitly admits that
rebuilding the same key can resolve newer npm dependency versions, so 'reproducible' is only approximate.
That is fatal for durable replay"_ (`simplification-ruminations-2026-07.md:2730`). If a clean-room
build capability wants replayable history, the resolved lockfile must be part of the key from day one —
that is a one-field decision now and an un-fixable one later.

### 3.5 — Secrets: the write door and the origin pin ⚠️ rank 5

**What is gone.** `itx.secrets.set` was deleted (`cccc4071d`); `SECRETS_KV` is read-only from userspace.
There is no origin pin, no `redirect: "manual"`, no audit event, and the material sits in KV as
plaintext. The parked plan is unambiguous: these **must be built-in** (D4) — a userspace target must
never see material, and the tail must substitute _after_ the last wrapper.

**Why it ranks fifth rather than lower.** The change is small (a built-in root plus a pin in the tail,
~80 lines) but the _grammar_ decision is urgent: apps/os writes `getSecret("/secrets/x", { field })`,
the clean room writes `{{secret:project:NAME}}`. Both already exist in this repo. Whichever survives
ends up baked into userspace code, config repos and docs — so it is cheap now and expensive later.

**Smallest change.** `itx.secrets.put(name, value, { origins })` + `.list()` as a built-in; the pin and
`redirect: "manual"` checked on the _final_ URL inside `itx.fetch`'s tail; one audit event per use;
Basic-auth peeling (git-over-HTTPS needs it); a `readable` birth flag for the project API key.
Encryption-at-rest is a further ~40 lines inside the same built-in. Refresh strategies that _compute_
with material (GitHub App RS256) cannot be userspace and are honestly deferred by the plan.

### 3.6 — Self-description: `instructions`, `types`, `__describe` ⚠️ rank 6

**The requirement, stated as loudly as anything in the corpus.** _"Agents are a first-class audience of
this system, and an agent's only sense organ is `describe()`. The acceptance test for every feature: an
agent with no prior knowledge, handed a stub, can act competently from `describe()` + `instructions` +
`types` alone"_ (`apps/os/docs/itx-later.md`). apps/os carries `instructions` and `types` on every
mount, validates the type declaration **at provide time**, serves descriptions from stored metadata
without dialling the (possibly offline) target, and truncates at 16 000 chars with a pointer to `itx.docs.get`.

**The tension.** The clean room's rewrite rule is `{ match, target }` and _nothing else_ — a ruling, not
an oversight (SYNTHESIS §7/§8: no offset, no policy, no flags). Adding `instructions`/`types` to that
event re-opens the door the onion closed.

**Smallest change that respects the ruling.** A **sibling event family**, not a fatter rule:
`itx/rewrite-rule-documented { match, instructions?, types? }`, reduced into its own core-state slice,
surfaced by `itx.rewriteRules.list()` as a join (the same shape as `subscriptions.list()` joining rows
with cursors). Provide-time _validation_ (compiling the declaration) stays out of the door — it becomes
`itx.docs.typecheck`, a sidecar worker, called when the author wants it.

**Residue.** apps/os's connect-time auto-typing (evaluate the expression once at provide time and ask
its `__describe()`) is a side effect at the door, which `provide` deliberately does not have. Leave it out.

### 3.7 — Platform bindings have no door at all ⚠️ rank 7

**The fact.** The built-in roots are `whoami · kv · append · read · waitForEvent · cd · fetch ·
rpcStubs · rewriteRules · facets · subscriptions · workers · runScript`. The `bindings` root that once
existed (`bindings.get('FALLBACK')`, increment 43) is gone. A confined worker gets only `env.ITX` and
`globalOutbound`. So **`env.AI`, `env.BROWSER`, `ARTIFACTS` (repos), R2 (files, workspaces, sandbox
snapshots), the `EMAIL` binding, Images/Videos, and the container namespaces are unreachable** — and
with them go seven of apps/os's eighteen domains.

**Why it is not rank 1.** The fix is one built-in root. Why it is on the list at all: it re-opens
"what is physical", and apps/os's own design says raw pass-through is the _degenerate_ case —
_"expect bindings to arrive wrapped"_ with gateway selection, attribution, and later quotas
(`apps/os/docs/itx-design.md` §2).

**Smallest change.** `itx.bindings.get(NAME)` returning an `InvokeHandle` over `env[NAME]`,
allow-listed by `APP_CONFIG` (so a deployment declares what it exposes, and "capability presence is
environment-determined" — ADR 0021 — is honoured). Everything wrapped-with-policy is then an ordinary
rewrite rule to a loaded worker that holds the binding handle plus the policy. One root, no new door.

### 3.8 — Cross-context copy without provenance, cycles, or a fence ⚠️ rank 8

A subscription targeting `itx.cd('/archive').append` delivers today. What it does not do: stamp
`source.copiedFrom`, cap the hop count, refuse a cycle, or reject a batch from a _destructively
recreated_ source. apps/os treats all four as load-bearing (`domains/streams/copy-appends.ts:1-35`),
because a copy chain is how one processor reacts to another stream at all
(D23: one processor, one stream — cross-post is the only join).

**Smallest change.** In the delivery loop, when a target's terminal is a sibling `append`: stamp a
`source.copiedFrom` hop (path, offset, subscription name, source `streamId`), refuse when the chain
already contains this context or exceeds the hop cap (ack-as-dropped + one idempotent audit event),
and carry the source `streamId` in the range so the receiver can fence a strictly older stamp.
~40 lines plus the `streamId` from §2.3. The JSONata transform explicitly does **not** come over.

### 3.9 — Delivery at scale: two silent platform ceilings ⚠️ rank 9

Two measured failures in apps/os, neither of which is visible in a test suite:

- **The subrequest budget.** One `/api` WebSocket, 12 000 events at 120/s → _delivery stopped at exactly
  10 000_. Appends kept succeeding, the socket stayed open and answered `runtimeState()`, no close, no
  error. Replacing the logical callback on the same socket did not recover; a new physical socket did.
  Mitigated with `limits.subrequests: 10_000_000`, which the task itself calls _"buys time, not a design"_
  (`tasks/redesign-high-volume-stream-delivery-transport.md`).
- **Subrequest depth.** `append → wake → deliver → append` chains hit `Subrequest depth limit exceeded`,
  which caused a durable subscriber to **permanently skip an event** and a processor host to enter a
  6-hour revival plateau only a deploy could reset (`tasks/prd-subrequest-depth-limit-breaks-deliveries.md`).

The clean room's delivery is faster (52 k ev/s local, p50 9 ms) and structurally lighter, but a lent
stub is still invoked over a Workers-RPC leg from the DO, and no measurement here has run long enough
to hit either ceiling. **There is no smallest fix — there is a measurement.** Count subrequests per
incarnation on a long-lived connected subscription before believing the current shape scales; the
pager/re-lend cycle is already the natural mitigation (a fresh leg resets the budget), so the design may
already be right for the wrong reason. Corollary: keep `append → deliver` from re-entering `append`
synchronously; the record's own rule is that real sends ride an alarm boundary
(`processors-jam.md:35-38`).

**The same measurement decides the voice question.** R4 makes real-time PCM a requirement
(`DESIGN.md:217-219`), and the clean room's answer is ephemeral events — now genuinely cheap (zero
writes, no transaction, 52 k ev/s locally). But the ruminations doc reverses that plan on volume
grounds: 50 frames/s/direction is **360 000 frame deliveries per hour** and 230–691 MB/h, against a
stream design that _"explicitly targets 10²–10³ events per second"_ — and _"an active call is not a
hibernation workload"_ (`simplification-ruminations-2026-07.md:4123-4307`). Most of its cited cost
(an SQLite row and a transaction per frame) no longer applies here. What remains unmeasured is the
per-frame delivery cost through the loop and the subrequest budget above. Measure a 50 Hz duplex
stream for an hour before committing either way; if it holds, the ephemeral lane is the answer and
the proposed device/FIFO transport is machinery we never build.

### 3.10 — Fan-out to many live clients under one name ⚠️ rank 10

apps/os fans a call out over _every_ connection at a client path (`Promise.all`, `[]` if none) — two
browser tabs both get `navigate(url)`. The clean room keys the stub directory by `rpcStubKey` and a new
pager **replaces** the old (newest wins, "a reconnect is not a detach"), so the second tab silently
orphans the first's rule.

**Smallest change, and the recommendation.** Do _not_ add a fan-out brand. Under trusted clients the
convention is cheaper: one key per connection (`itx.tabs.<id>`) plus a subscription each, and a rewrite
rule naming the group only if a group is ever needed. Document it, because "provide the same match from
two tabs" is the obvious wrong thing and it fails quietly. (If a real caller is burned, the door is
`RpcStubDirectory` holding a _set_ per key with a `fanOut` delivery — but that is speculative machinery
by the standing doctrine.)

### 3.11 — Deletion, GC, and the end of a context's life ⚠️ rank 11

_"Since the itx-v4 cutover there is deliberately NO way to delete a project"_ (`tasks/os-project-archival.md`),
and Cloudflare offers **no API to delete DO instances** — the only reclaim path is a
`deleted_classes` migration dance (`worker-topology.md:76-89`). The clean room can delete a facet
(`itx.facets.delete`) and nothing else. TTL/offload mechanics are explicitly pinned by the owner:
_"do not design TTL / offload mechanics now"_ (`DESIGN.md:945-953`).

**Smallest change.** One built-in `itx.delete()` that appends a terminal `context/deleted` tombstone,
refuses every later append (the `paused` check already has the shape), and `deleteAll()`s storage — plus
the control plane freeing the globally-unique slug. That makes archival expressible without designing
retention. Everything else stays parked.

### 3.12 — Observability and metering ⚠️ rank 12

The clean room kept `logs.ts` (warn only) and trimmed `reportIssue`. apps/os runs full Workers
observability (persisted logs + traces, 7-day retention) and an `itx-observability` hook that journals
every capability invocation — the design's stated _"usage/billing events for every cap uniformly"_
(`itx-design.md:287,531`). There is **no tail-worker design anywhere in either corpus**; observability
is Workers Logs + Traces + stream events.

**Smallest change.** One ephemeral event at the dispatch point (`itx/invoked { match, ms }`) that
nothing consumes unless a subscription names it, plus `tail_consumers` in wrangler when a consumer
exists. Cheap, and consistent with "event volume is fine" and D14 (billing is userspace).

**The gap worth naming loudly**, because the record already does: _"allowed egress leaves NO trace…
A project cannot enumerate all bytes that left"_ (`core-model-grounding.md:75-93`). Once the fetch
rules land (§3.3), the tail is the natural place to emit one usage fact per egress — otherwise the
metering story has no data.

## 5. Contradictions and loose ends worth a decision

1. **Two name codecs in-tree.** `packages/v3/control-plane-shell` builds `${projectId}.iterate${path}`;
   `apps/kernel/src/stream-do.ts` uses `<projectId>::<path>`. D25 retired `::`; the kernel is frozen but
   still in the workspace.
2. **Two secret grammars in-tree** (§3.5). Pick one.
3. **Egress direct vs through the control plane in self-host** — `issues/11` says direct was restored;
   ADR 0035 (later) says _"Egress STILL always flows through the control plane."_ ADR 0035 is the later text.
4. **"There is only `fetch`, not egress" (D20)** vs `itx.egress` in `target-core.md` and D32's "two
   fetches, don't conflate". The clean room resolved it (`itx.fetch` is the tail) — the docs have not.
5. **R11 "a processor must be hostable anywhere, including by a third party"** vs the ruling that all
   processors run in facets. Recorded as a live tension, not a bug.
6. **ADR 0005 says there is no reveal lane; the shipped surface has `Secret.reveal()`** for a secret
   born `readable: true` (`itx-api.generated.ts:1641-1684`) — an immutable birth fact, mutually exclusive
   with an egress pin. Either the ADR predates the born project API key or `readable` is its documented
   exception. Decide which before copying the invariant verbatim.
7. **Serving is a hole in v3.** `packages/v3/control-plane/src/ingress.ts` resolves `host → {projectId, app}`
   but its dial half _"was DELETED in clean-room increment cook-1"_ — nothing in v3 routes a resolved
   project host to running project code today. §3.3 is the plan that closes it.
