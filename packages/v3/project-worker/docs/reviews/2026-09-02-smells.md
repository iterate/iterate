## Summary (5 lines)

1. The vocabulary is mostly right. What is left is **residue from deleted designs** (the capability
   table, `routing.ts`, transport ids) and **one word carrying two or three referents** (`host`,
   `target`, `ref`, `sub`, `hooks`, `resolve`). Every fix is a rename to a spelling that already
   exists in the code — no noun is coined anywhere in this report.
2. **17 DO-NOW items, about −90 lines net.** Two are more than cosmetic: `enableProcessor` cannot
   carry a `cacheKey`, so the only durable processor door cannot host a producer source (the `/demo`
   regression this exposed is already fixed at `4af9b3f76` by handing the modules over literally);
   and two of the three "stub not reachable" exits are uncoded, so the delivery loop logs the
   designed heal path as `push delivery dropped`. The other fifteen are renames or dead-state deletions.
3. **Nine deletions** carry the LOC: a 32-line logger with one call site, a write-only `inFlight`
   counter, three SDK members no author uses, a lazily-born `LiveState` holder with an unreachable
   fallback and a false comment, a caller-invented `where` prefix, a string door on `InvokeHandle` that
   cannot parse, a coined `WebSocketHooks` type, and the facet spec's six spellings collapsing to one.
4. **11 MENU items.** Two are real decisions, not tidying: give the core reduce its own root
   (`itx.core.snapshot()`) instead of a reserved facet name (about 22 files; reverses a deliberate
   uniformity), and let the relay use the one step-walker (−16 lines, but it must preserve the
   one-round-trip pipelining commit `72378b0e5` just bought, so the wire-frame e2e gates it).
5. Six items drew a split vote (do-now vs menu); the dissent is on each line. Nothing here needs
   re-litigating: REJECTED lists the three routed performance filings and the sub-proposals the
   judges declined inside accepted findings.
