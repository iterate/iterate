# Layering review — 2026-09-02

> Read against `LAYERS.md`, `docs/itx-surface-as-built.md`, `docs/design-onion-subscriptions-processors.md`
> and the last ~12 `BUILD-LOG.md` entries. Every non-test file in `src/` read. Nothing edited.

## Summary (5 lines)

1. The onion mostly holds: layers 0–3 are real modules with real seams, and the two vocabularies
   (physical rpc stubs vs pure rewrite rules) never mix. The leaks that remain are few and specific.
2. There are exactly **three upward arrows**: layer 1 and layer 3 import `stream/processor.ts`
   (layer 4) for `consumesEvent`/`ScannedRange`, `events.ts` ⇄ `processor.ts` is a type cycle, and
   the delivery loop calls a processor-host method by name (`catchUpFromLog`).
3. There are **two live double-owners**: `itx.facets.delete` vs the subscription row that hosts a
   facet (the built-in is dead code AND breaks the invariant), and `provide`/`subscribe` each
   re-implementing the lend→append→rollback dance (with `subscribe` missing the rollback).
4. The edge is an honest proxy in every case that matters; the parts that are not proxying
   (`cd`, the lend, the four verbs) each have a reason. The dishonesty is elsewhere: `ItxEntrypoint.get()`
   hands loaded code the _edge_ class with a throwaway `SessionTeardown`.
5. Shape: the DO is two things glued (a context + a facet host); `processor.ts` is two things glued
   (the pure author class + the engine); the delivery loop keeps one subscription's runtime in five
   parallel maps. Three splits/merges, no new abstractions, ≈ −150 lines net.

## Findings, ranked by leverage

### F1 — `itx.facets.delete` is a second owner of "does this facet exist", and nothing calls it

`src/context/built-ins.ts:116-122` (interface), `:285-306` (impl) · `src/iterate-context-durable-object.ts:284-288`, `:538-547`

**The story.** §9 of `itx-surface-as-built.md`: "the raw event IS the disablement" — a
`subscription-configured { name, target: null }` deletes the facet its row hosted. One door.

**The code.** There are two doors. Besides the removal effect, `itx.facets.delete(name)` is a public
built-in verb. It has **zero call sites**: not in `src/`, not in `e2e/`, not in `__workers-tests__/`
(the one grep hit, `__workers-tests__/alarm-quiesce.test.ts:174`, is a stale comment describing the
old two-step `disableProcessor`). The DO's removal effect calls `#deleteFacet` directly, not through
the built-in.

**Why it matters.** It is not merely dead — it is _wrong_. Calling it on a processor deletes the
memo and the facet, but leaves the subscription row, whose target still carries the full hosting
spec (`itx.facets.get(name, { source, className })`). The next commit's delivery loop evaluates that
target, `#invokeFacet` re-writes the memo (`:433-441`) and re-hosts the class. So the delete is
silently undone one commit later, with the facet's storage gone: a rebuilt-from-scratch processor
masquerading as a resumed one. The one-owner rule the review decided is enforced only by nobody
having called the other door yet.

**Recommendation.** Delete `facets.delete` from `BuiltInScope`, from `buildBuiltIns`, and from
`BuildBuiltInsDeps`; keep the DO's private `#deleteFacet` for the removal effect. **−18 lines,
3 files, no test changes.**

### F2 — the DO decodes a layer-3 row's grammar to decide a layer-4 fact

`src/iterate-context-durable-object.ts:197-234`

**The story.** Layers use only what is below them; "nothing is declared or stamped" — the delivery
loop asks the _value_ what it is, never the string.

**The code.** `#deleteFacetsWhoseHostingSubscriptionWasRemoved` does exactly the string/shape sniff
the delivery loop was designed to avoid, one layer down:

```ts
const [, root, getStep] = removedRow.target;
if (root === "facets" && Array.isArray(getStep) && getStep[0] === "get" && getStep.length >= 3 …)
  this.#deleteFacet(getStep[1]);
```

**Why it matters.** The grammar of a subscription target is owned by `stream/subscriptions.ts`
(layer 3) and written by `enableProcessor` (layer 5). It is _read_ structurally in the DO. Change
the spelling `enableProcessor` emits — insert a step, move `name` — and this silently stops
matching: `disableProcessor` becomes a no-op on the facet, which then lingers, un-quiesced, with
orphaned storage, and the next enable resumes from it. There is no test that would fail on the
spelling change alone, because the rule lives nowhere it can be table-tested.

**Recommendation.** Move the sniff into `stream/subscriptions.ts` as one exported pure function next
to the builder that writes the shape — `facetHostedBySubscriptionTarget(target): string | null` —
with a table test (`{ target, hosts }` rows), per the rule-module doctrine. The DO's effect becomes
three lines. **Moves 12 lines, adds ~8 rows of table test; the builder and the reader of the same
grammar end up in one file.**

### F3 — layer 1 and layer 3 import layer 4, and `events.ts` ⇄ `processor.ts` is a cycle

`src/stream/stream.ts:40` · `src/stream/subscription-delivery.ts:31` · `src/stream/events.ts:155` ⇄ `src/stream/processor.ts:49-52` · `src/stream/processor.ts:88, 106-117`

**The story.** "Each layer only uses the ones below it." The stream (layer 1) and subscriptions
(layer 3) are below processors (layer 4).

**The code.** `stream.ts` imports `consumesEvent` from `processor.ts`. `subscription-delivery.ts`
imports `consumesEvent` **and** `ScannedRange` from `processor.ts`. And `events.ts` imports
`EventDefinition`/`ProcessorContract` _from_ `processor.ts` while `processor.ts` imports
`StreamEvent`/`StreamEventInput` _from_ `events.ts` — a type-level cycle between the two most-used
modules in the package.

**Why it matters.** Concretely: the stream cannot be read, tested, or reasoned about without the
560-line processor file in scope, and `processor.ts` is the file that carries the whole
`ProcessorEngine` (serial chain, gap repair, version re-reduce, live-state publishing). Someone
extracting the kernel — or bundling the SDK — has to drag layer 4 along with layer 1. The cycle also
means `knip`/tree-shaking can never split the SDK bundle from the kernel.

**Recommendation** (one move, fixes all three arrows and half of F-shape below):

- Move the _vocabulary_ down: `consumesEvent`, `ScannedRange`, `EventDefinition`, `ProcessorContract`
  into `stream/events.ts` (they are statements about events and event contracts, not about
  processors). `events.ts` then imports nothing from `processor.ts`; the cycle dies; `stream.ts` and
  `subscription-delivery.ts` import only `events.ts`.
- Split the engine out: `stream/processor.ts` keeps `StreamProcessor` (the pure author class, ~40
  lines — which is legitimately layer-1 vocabulary, since `CoreStreamProcessor` extends it);
  `stream/processor-engine.ts` takes `ProcessorEngine` (~400 lines). Nothing below layer 4 imports
  the engine.

**≈0 net lines, 2 files touched + 1 new file; `processor.ts` drops 560 → ~140.**

### F4 — `provide` and `subscribe` each re-implement the lend/append/rollback dance, and only one rolls back

`src/iterate-context.ts:194-238` and `:251-286`

**The story.** `provide` is THE ONE FRONT DOOR for making a name mean a live thing; `subscribe` is
"build the event, append it", with a lend when the target is live.

**The code.** Both do: canonicalise a key → `lendRpcStubOverPager` → `sessionTeardown.add` → build
the event → `#append` → return a handle whose disposer branches on whether the target was a lent
stub (dispose the pager, and let the DO un-set) or an expression (append `null` in the background).
Two copies, and they differ:

- `provide` wraps the append in `try/catch` and disposes the lend on refusal (`:229-236`), with the
  comment "or a stub nothing names would linger for the session".
- `subscribe` does **not** (`:261-276`). A `subscribe(fn)` against a paused stream throws
  `STREAM_PAUSED` _after_ the pager is open and registered: the stub stays in
  `itx.rpcStubs.list()`, an `rpc-stub/attached` ephemeral has already fired, and nothing names it
  until the session ends. That is the exact leak `provide`'s catch exists to prevent.
- `provide(match, null)` returns `new RewriteRuleHandle(() => undefined)` (`:203`) — a disposable
  that disposes nothing, purely to satisfy the return type.

**Why it matters.** One decision — "how does a live target become a durable name, and who undoes
it" — is spelled twice, and the second spelling is missing a rule. Any future change to the lend
protocol (a second dup, an idle policy in `options`) has to be made twice.

**Recommendation.** One private method on `IterateContext`:
`#lendAndAppend(rpcStubKey, target, buildEvent): Promise<() => void>` — lend if live, register, build,
append, roll back on throw, return the right undo. `provide` and `subscribe` become ~8 lines each.
**−35 lines, 1 file, fixes the subscribe rollback gap for free.**

### F5 — the processor's whole source text is copied into the log, the core checkpoint, and every live-state delta

`src/iterate-context.ts:301-312` · `src/stream/subscriptions.ts:296-308` · `src/stream/core-processor.ts:205-224` · `src/stream/stream.ts:352-369, 383-386`

**The story.** "A subscription is pure data: a name, a target expression, an optional filter."

**The code.** `enableProcessor` puts the _entire_ hosting spec — `{ source: { "cap.js": …the whole
module text… }, className }` — inside the target expression. `subscriptionConfiguredEvent` prints
that expression into the event payload (JSON5 inside a string). Then:

1. the event body is a durable row (chunked over 512 KiB — `stream.ts:498-534`);
2. the core reduce parses it and stores the parsed object in `state.subscriptions[name].target`
   (`core-processor.ts:218`), which is written into the core **checkpoint blob** on every core state
   change (`stream.ts:363-369`);
3. the core `LiveState` diffs old→new state and emits an `add` op whose value is that row — so
   **enabling a processor broadcasts its source code as a live-state delta** to every subscriber of
   `events.iterate.com/live-state/changed` (the `/demo` page included), and re-emits the whole
   subscriptions map shape on every later core change that touches it;
4. `itx.subscriptions.list()` prints it again per row (`iterate-context-durable-object.ts:327`);
5. the same spec is _also_ the facet startup memo in DO kv (`:430-441`).

**Why it matters.** A 300 KB processor bundle becomes ≥ 3 durable copies plus an ephemeral broadcast,
and every unrelated core-state change (a rewrite rule set, a pause) rewrites a checkpoint that
carries all of them. This is invisible today because the e2e fixtures are tiny.

**Recommendation.** Measure first (append a realistic processor, then `itx.read()` the row size and
the checkpoint size — a counter is a hypothesis). Then the cheap, deletion-shaped fix: have
`CoreStreamProcessor.projectLiveState` publish subscription rows with the target _printed and
spec-elided_ (`itx.facets.get('presence', …).processEventBatch`), so the live view stays truthful and
the wire stays small — ~10 lines in `core-processor.ts`. The producer-expression + `cacheKey` path
(already built, `worker-loader.ts:121-131`) is the escape hatch for large sources and should be what
the processor docs recommend. The structural alternative — the row names only the facet and the memo
is the single home of the spec — is a doctrine change (it gives up "a re-enable rebuilds from the
log") and is the owner's call, not this review's.

### F6 — `ReachableContext` is a third name for a context, defined in the wrong layer, to paper over one sync method

`src/stream/stream.ts:565-598` · `src/context/built-ins.ts:21, 164-166, 267-282`

**The story.** One door per concept; a context is `IterateContextDurableObject`, and the edge
`IterateContext` is a proxy in front of it.

**The code.** `stream/stream.ts` — the commit point, layer 1 — ends with a _context_ interface
(`append`/`read`/`invoke`) plus `localReachableContext`, an adapter whose only job is to make the
DO's synchronous `read` async. `built-ins.ts` (layer 0) imports it back up from layer 1 so `cd` and
`append`/`read` can type their seam.

**Why it matters.** Three names for "a context you can reach" (`ReachableContext`,
`IterateContext`, the DO), and the layer-0 → layer-1 import exists only for this interface. The
adapter is pure ceremony: `DurableObjectStub<IterateContextDurableObject>` already satisfies the
shape structurally; the local case does not because one method is sync.

**Recommendation.** Make `IterateContextDurableObject.read` `async` (its only in-process caller is
the adapter; `Stream.read` stays sync and is untouched), then delete `ReachableContext` and
`localReachableContext`, and type `BuildBuiltInsDeps.context` as
`(path: string) => IterateContextDurableObject | DurableObjectStub<IterateContextDurableObject>`.
The DO passes `this` for its own path. **−30 lines, 2 files, and layer 0 stops importing layer 1.**
(Verify the `cd` append/read fast path — `built-ins.ts:273-282` — still typechecks against the
union; it calls only the three shared members.)

### F7 — the terminal-`fetch` shape is pattern-matched in four places

`src/iterate-context.ts:166-176` · `src/context/rpc-stub-directory.ts:148-159` · `src/iterate-context-durable-object.ts:491-494` · `src/fetch/rpc-stub-fetch.ts:53-61`

**The story.** Doctrine point 1: "a fetch-shaped capability is ALWAYS called through a terminal
`fetch`… `itxExpressionEndingInFetch` is the one normalizer that enforces the spelling."

**The code.** It is the one normalizer for the _lane_. The _fork_ — "the last step is a `fetch` call
carrying a live `Request`" — is written out longhand three more times, each with the same four-part
condition (`Array.isArray(last) && last[0] === "fetch" && last.length === 2 && last[1] instanceof Request`),
in the edge, in the rpc-stub directory, and in the facet door (where it is spelled differently
again: `steps.length === 1 && first[0] === "fetch"`).

**Why it matters.** Four copies of one predicate that decides which _transport channel_ a call takes.
The facet copy already diverges (it only matches a single-step call). A change to the spelling — the
anonymous call step, an extra arg — has to be found in four files by grep.

**Recommendation.** Export one predicate from the file that owns the doctrine:
`terminalFetchRequest(expr: ItxExpression): { head: ItxExpression; request: Request } | null` in
`fetch/rpc-stub-fetch.ts`, above the WORKAROUND fence, and call it from all four sites.
**−20 lines, 4 files, one concept spelled once.** (It also gives the delete-day checklist one more
call site to enumerate, which is a feature.)

### F8 — the delivery loop knows a processor-host method by name

`src/stream/subscription-delivery.ts:105-132` (line 125: `await head.invoke([["catchUpFromLog"]])`)

**The story.** Layer 3 knows the stream and the codec, and asks the evaluated value only _what it
is_ (a brand), never what it can do. Processors (layer 4) are sugar on top.

**The code.** On `subscription-configured`, the loop evaluates the target head and, if it is a
`FacetHandle`, calls `catchUpFromLog()` on it — a method that exists only on
`sdk/stream-processor-durable-object.ts`. A hosted facet that is _not_ a processor (a chatroom, a
lobby — the shape `sdk/index.ts` documents) gets a `NOT_A_METHOD` error, swallowed as an issue report.

**Why it matters.** It is the only place in layers 0–3 that names a layer-4 contract, and it is
redundant: `ProcessorEngine.processEventBatch` already gap-repairs from its own cursor
(`processor.ts:284-293`), and `snapshot()`/`liveSnapshot()` catch up on read (`:246, :340`). The eager
call buys "materialised at enable time", which the _head evaluation on the line above_ already
does.

**Recommendation.** Delete the `catchUpFromLog` invoke and the `FacetHandle` check around it; keep
the head evaluation (that is the materialisation + the once-only error report). **−7 lines.** Re-run
the lineage/processor e2e lane: if something pins "enabled ⇒ caught up before the first matching
event", that pin is the honest place to state the requirement, and it should then be expressed as
`processEventBatch([], { after: 0, through: head })` — a push, in the loop's own vocabulary — rather
than a foreign method name.

### F9 — two post-commit doors: `Stream.append` and `IterateContextDurableObject.append`

`src/iterate-context-durable-object.ts:197-206` · `src/stream/stream.ts:251, 374-387` · `src/stream/subscription-delivery.ts:356`

**The story.** "The DO has `append` and no configuration verbs" — one commit point, one tail.

**The code.** There are two appends with different tails. `Stream.append` runs waiters → `onCommit`
(delivery) → the core live-state delta. `IterateContextDurableObject.append` additionally captures
the pre-commit subscriptions, records quiet-clock activity, and runs the facet-delete effect. Callers
are split: the edge, `#unsetWhatNamesRpcStub` and loaded code go through the DO's; the wake record
(`stream.ts:190-203`), the core live-state sink (`:353-355`) and the delivery loop's halted fact
(`subscription-delivery.ts:356`) go through the Stream's.

**Why it matters.** The facet-delete effect is not a property of "a subscription row was removed",
it is a property of "a subscription row was removed _through this door_". Today no inner caller
appends `subscription-configured { target: null }`, so nothing is broken — but it is latent, and it
is exactly the kind of thing a future policy processor (a GC facet that disables a stuck processor
by appending the raw event) would trip over, silently leaking a facet.

**Recommendation.** Give `onCommit` the pre-batch core state as a fourth argument
(`Stream.append` already holds `reducedStateBefore` at `:358`) and move both tail effects into the
DO's `onCommit` closure. `IterateContextDurableObject.append` becomes a one-line delegate; there is
one commit tail. **−10 lines, 2 files.** One behaviour delta to accept or preserve: a fully-deduped
batch returns before `onCommit` (`stream.ts:328`), so it would stop arming the quiet clock — arguably
more correct (nothing landed), but say so in the commit.

### F10 — a subscription's delivery state lives in four containers with two owners

`src/stream/subscription-delivery.ts:43-48, 66-75, 94-104, 278-290, 328-348` · `src/stream/core-processor.ts:80-88, 225-262` · `src/iterate-context-durable-object.ts:322-342`

**The story.** "A facet or a lent stub owns its progress; anything else, the stream keeps a cursor."
One owner per fact.

**The code.** For a cursor subscription the facts are split:

| fact                                                                                         | home                                                    | owner           |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------- | --------------- |
| `confirmedOffset`, `attempt`, `nextAttemptAtMs`                                              | `#cursors` (memory) + `subscription-cursor:<name>` (kv) | the loop        |
| `halted`                                                                                     | the log → core state                                    | the core reduce |
| `resumed { afterOffset, atOffset }`                                                          | the log → core state                                    | the core reduce |
| `resumeAppliedAtOffset`                                                                      | the cursor (kv)                                         | the loop        |
| `lastDeliveredThroughOffset`, `pushedEventBatches`, `deliveryChain`, `cursorDeliveryRunning` | four more maps (memory)                                 | the loop        |

A resume therefore takes a **two-store handshake**: the reduce records `resumed.atOffset`, the loop
compares it against `resumeAppliedAtOffset` in kv (`:278-290`), and the failure path re-checks it a
third time (`:344-348`, "a delivery-resumed that landed DURING this attempt"). Meanwhile the loop
_already_ reacts to the resumed event directly in `onCommit` (`:94-104`).

**Why it matters.** Three code paths for "apply the operator's seek exactly once", one of which
exists only to undo a race the other two create. The `resumed` field is also permanent state in the
core checkpoint for a transient operator action.

**Recommendation, in two independent halves:**

- _(a)_ Keep `subscription-delivery-resumed` clearing `halted` in the reduce (durable, correct), and
  apply the **seek** where the loop already sees the event — in `onCommit`. Then delete `resumed`
  from `CoreState`, its reduce case, `resumeAppliedAtOffset` from the cursor, the `:278-290` block and
  the `:344-348` re-check. **−35 lines across 2 files.** The accepted loss: a seek issued in the
  instant before an eviction is not replayed (the un-halt still is) — which matches how an operator's
  live action behaves everywhere else.
- _(b)_ Collapse the five per-name maps into one `Map<string, SubscriptionRuntime>`;
  `#forgetSubscription` becomes a single `delete`. **−15 lines, one deletion path instead of five
  that must be kept in sync** (today `#cursorDeliveryRunning` is deliberately not in it, which the
  reader has to verify by hand).

### F11 — `ItxEntrypoint.get()` hands loaded code the edge class with a throwaway session

`src/itx-entrypoint.ts:27-34`

**The story.** "The edge is a proxy in front of the DO… every lend is undone at session end by the
session's `SessionTeardown`."

**The code.** `get()` builds `new IterateContext(env.ITERATE_CONTEXT, address, new SessionTeardown(), waitUntil)`
— a **fresh, unowned** teardown per call, which nothing ever calls `disposeAll()` on. The docstring
says "this hop lends nothing session-long", which is a convention about how loaded code _should_
behave, not something the type or the code enforces: `provide(match, liveStub)` and `subscribe(fn)`
are right there on the returned object.

**Why it matters.** A loaded worker (or a userspace processor's effect) that calls
`itx.provide("itx.cb", fn)` opens a pager socket registered in a map that is dropped on the floor
when the call returns. Nothing recalls it; the DO keeps a pager-backed presence entry until the
socket dies on its own, and the rewrite rule it wrote survives with it. The "session-scoped" contract
of the verb is simply not true in this scope.

**Recommendation.** Two options, both small: (i) hold **one** `SessionTeardown` as a field on the
`ItxEntrypoint` instance and dispose it in a `[Symbol.dispose]`, making the lifetime the stub's, or
(ii) make the honest statement executable — have `get()` return the context with a teardown whose
`add()` throws (`"a loaded worker cannot lend a pager — pass callbacks as call args"`). **~8 lines
either way.** (ii) is the one that matches the docstring; (i) is the one that keeps the surface
uniform. Owner's call — but the current state (a silently-dropped teardown) is neither.

### F12 — the DO is a context glued to a facet host

`src/iterate-context-durable-object.ts:344-547` (204 of 674 lines)

**The story.** Layer 0's physical registries each own their table: `RpcStubDirectory` is a module,
`Stream` is a module, `SubscriptionDelivery` is a module.

**The code.** The facets registry is not: `#invokeFacet` (137 lines: memo read/write, load, racing
delete check, version marker, abort, watchdog, result copy/dispose), `#deleteFacet`, `#liveFacetNames`,
`#facetWorkInFlight`, and the facet half of `alarm()`/`#recordActivityForQuietClock` all live inline
in the DO, interleaved with the fetch door, egress, and the rpc-stub verbs.

**Why it matters.** It is the one physical registry with no seam, and it is the largest single unit
of behaviour in the package. The quiesce clock (`:344-391`) has to reach into both `#liveFacetNames`
_and_ `#rpcStubs.hasBorrowedRpcStubs()`, so the reader must hold two registries' internals at once to
follow one alarm.

**Recommendation.** Extract `context/facet-host.ts` — `class FacetHost { invokeFacet(ref, steps);
deleteFacet(name); abortIdleFacets(); hasLiveFacets(); workInFlight }` — constructed with
`{ ctx, env, itxHost, iterateContextName, invoke, recordActivity }`, mirroring `RpcStubDirectory`
exactly. The DO drops to ~470 lines and its `alarm()` reads as "quiesce both registries".
**Moves ~200 lines, 1 new file, no behaviour change.** (`#egress`, `:614-641`, is another 28-line
guest with a natural home next to `@v3/shared/egress`; lower priority.)

### F13 — small stuff, each cheap

- **`rewriteRules` is a formatting view of a state slice that is already reachable**
  (`iterate-context-durable-object.ts:293-303`, `built-ins.ts:106-109`): `itx.facets.get('core').snapshot().state.itxExpressionRewriteRules`
  is the same data, minus the printing. Unlike `subscriptions.list()` — which genuinely joins the
  loop's cursors — this root adds only `print()`. Deleting it is −25 lines and one fewer built-in
  root; keeping it is defensible ergonomics (the state holds parsed halves, the view holds strings).
  Owner's call; do not have both stories in the docs.
- **`runScript` is the one built-in that is sugar over another built-in**
  (`built-ins.ts:39-53, 146-148, 328-329`, ~25 lines, one e2e user in `load-sources.e2e.test.ts`).
  Deleting it makes "one door per host kind" literally true; the wrapper template can live in the
  test that wants it. Low stakes either way — but note it is the only surviving example of the shape
  the `load`/`getEntrypoint` deletion was meant to kill.
- **Two encodings on one header.** `worker.ts:77-81` puts a _dotted_ expression in
  `x-itx-expression`; `iterate-context.ts:173-174` puts _JSON_; the DO sniffs `startsWith("[")` to
  choose a parser (`:578-580`). The codec round-trips — have `worker.ts` normalise
  (`JSON.stringify(parse(itx))`) and delete the fork. **−4 lines.**
- **`#unsetWhatNamesRpcStub` swallows durable failures** (`:144-155`): each un-set is
  `void this.append(...).catch(() => undefined)`. For the ephemeral presence event that is right
  (documented); for the _durable_ rule/subscription removal it means a stream that happens to be
  paused when a client disconnects keeps the dangling rules forever, with no trace. Route those two
  through `reportIssue`. **+2 lines** (the one place in this review where adding beats deleting).
  Also note the match is exact-target only: a rule that reaches the stub through _another_ rule is
  not un-set — acceptable, but it is the presence-vs-rule-table gap and should be stated in `LAYERS.md`.
- **Identity is derived three ways** — `#name` (the DO name), `whoami()` (the closure), and
  `state.projectId/path/createdAt` (the birth certificate). All three are cheap and one of them
  (`whoami`) is the only non-materialising probe. Not worth changing; worth _saying_ in `LAYERS.md`
  that the DO name is the truth and the reduced copy is the log's echo.
- **The edge's six declared verbs are unspellable as rewrite matches — but only at the edge.**
  `installPrototypeInvokeFallback` lets declared methods win (`iterate-context.ts:352`), so a rule
  matching `itx.subscribe` fires inside the DO (nothing there declares it) and never through a
  client. Either refuse those matches in `rewriteRuleConfiguredEvent` or document the reserved list

- **Doc/code mismatch:** `LAYERS.md` says "a subscription's id is the offset of its
  subscription-configured fact". In the code the **name** is the identity (the map key,
  `#forgetSubscription`, the cursor key); `configuredAtOffset` is only the cursor's birth point
  (`subscription-delivery.ts:274`). Fix the sentence, not the code.
- **`stream.ts` also owns the row codec** (`:496-544`, chunking + reassembly, ~50 lines). If the file
  needs to come down after F6, that is the clean 50 to move (`stream/event-rows.ts`); it is not
  urgent — chunking is genuinely part of "what a commit writes".

## Things that are RIGHT — do not re-litigate

1. **The two vocabularies stay apart.** `rpc-stub-directory.ts` never parses a key; the rewrite table
   never holds a socket; the log records the rule, never the transport. This is the load-bearing
   decision of the whole design and the code honours it everywhere.
2. **The un-set of a live stub's rule belongs to the DO, not the session** (`:128-155`,
   `rpc-stub-relay.ts:119-124`). The reconnect-replaces-pager argument is correct and the edge's
   teardown correctly only closes the pager. Keep.
3. **`FacetHandle` / `RpcStubHandle` as empty brands** (`invoke-handle.ts:147-149`). Two lines that
   let the delivery loop ask the value what it is instead of parsing a target. Not duplication —
   they are the _only_ thing standing between this design and a `kind` flag on an event.
4. **`InvokeHandle` being a genuine `RpcTarget` and the prototype hop, not a `Proxy`.** The
   workerd#6873 reasoning in `dotted-path-proxy.ts:113-140` is right and hard-won; so is
   `Reflect.apply` over `stub[m].apply` in `dispatch.ts:37-42`. Do not "simplify" either.
5. **The core reduce living inside the commit transaction, with its checkpoint written in the same
   transaction** (`stream.ts:329-370`). This is what makes the pause check, the dispatch table and
   the subscription rows synchronously readable at every door. It is the reason the DO has no
   configuration verbs and should not be softened.
6. **The ephemeral fast path** (`stream.ts:330-333`) — zero writes, not even the high-water mark —
   and the `read()` proof capped at the durable mark (`:427-434`). Subtle, correct, and the comments
   earn their length.
7. **`consumesEvent` as the single consumes rule** (wherever it ends up living after F3). One rule,
   three callers, no drift.
8. **The `WORKAROUND` fence and its delete-day checklist** in `fetch/rpc-stub-fetch.ts:63-93`. The
   right way to carry a platform workaround: named, fenced, with the deletion enumerated.
9. **`cacheKey` as a dollar amount** (`worker-loader.ts:81-99`) and `facetLoaderOwner`'s
   length-prefixed composition (`:36-44`). Both are scar tissue with the incident attached; keep the
   comments verbatim.
10. **Both `cd`s.** The edge `cd` returns an edge context so a later `provide` lends in this session;
    the built-in `cd` serves expressions evaluated inside the DO. One resolver
    (`resolveContextPath`), two evaluation sites. §12's "keep both" is correct — the duplication is
    in `ReachableContext` (F6), not in `cd`.
11. **`enableProcessor` / `disableProcessor` as the one durable pair, with `disableProcessor` a
    single append.** The verb and the raw event now agree, which was the point.
12. **`lib/errors.ts`'s code-over-name doctrine** and `RPC_STUB_OFFLINE` re-coding at the relay
    (`rpc-stub-relay.ts:79-86`). Classify by code across a hop; the local re-code is the right place.
